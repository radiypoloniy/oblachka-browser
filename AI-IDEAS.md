# Идеи AI-фишек — отобранные по критерию пригодности

Список составлен ПОСЛЕ выполнения программы «локальный AI по делу» (все восемь срезов сделаны,
см. `CLAUDE.md`). Каждая идея прогонялась через тот же фильтр, что и сделанное:

1. **Короткий вход и короткий выход** — не «прочитай страницу и напиши эссе».
2. **Ответ жёсткой формы, который валидирует код** — номер из списка, помеченные строки, имя.
3. **Один шаг без плана** — 9B не планирует на длинном горизонте.
4. **Ошибка дешёвая и видна человеку** — предложение, а не действие; отмена в один жест.
5. **Данные личные** — то, чего облако не может в принципе, а не то, что оно сделает лучше.
6. **Анти-критерий:** если результат мысленно сравнят с ChatGPT в лоб — не брать.
7. **Отсеивающий вопрос:** не решается ли задача обычным кодом ЛУЧШЕ?
8. **Модель опциональна** — фича обязана иметь рабочий путь без скачанной модели.

Приоритет — по отношению «польза / объём работ». В скобках у каждой — что переиспользуется,
потому что почти всё здесь строится на уже написанном.

## 1. Разбор скопированного адреса в поля формы ⭐

**Что.** Человек копирует из письма или мессенджера строку вида «Иванов Иван Петрович, 123456,
Москва, ул. Ленина 1 кв. 5, +7 900 123-45-67» и вставляет её в ЛЮБОЕ поле формы доставки.
Браузер предлагает разложить её по всем полям сразу — поповером «Разложить по полям?» с
предпросмотром.

**Форма ответа.** Помеченные строки (`NAME:`, `POSTAL:`, `CITY:`, `STREET:`, `PHONE:`), каждая
разбирается отдельно и независимо от соседних — ровно как в `RuleParser.ts`. Индекс и телефон
дополнительно проверяются кодом по маске; не прошедшее проверку поле просто не подставляется.

**Почему проходит.** Вход — одна строка, выход — пять коротких. Ошибка видна мгновенно (поля на
экране) и отменяется через Ctrl+Z, потому что вставка идёт тем же `execCommand('insertText')`,
что и правка текста. Данные предельно личные — домашний адрес и телефон наружу не уходят вовсе.

**Почему не обычный код.** Порядок частей произвольный, разделители любые, «кв. 5» может быть
отдельным полем или частью улицы, отчество бывает и не бывает. Регулярками ловится индекс и
телефон — то есть ровно два поля из шести.

**Где живёт.** `AutofillOrchestrator.ts` + `AutofillPopoverManager.ts` (поповер уже есть),
детект полей — готовый `preload-content.ts`. Тем же разбором заводится профиль в настройках:
вставил строку — получил заполненную карточку адреса вместо десяти полей руками.

**Объём.** Средний. Инфраструктура вся на месте, новое — один промпт и валидация.

## 2. Папка для новой закладки ⭐

**Что.** Человек жмёт звезду и получает меню закладки. Предлагаем ОДНУ папку из уже
существующих — предвыбранной, с прежним списком папок рядом. Сейчас разбирать закладки по
папкам приходится потом, то есть никогда.

**Форма ответа.** `ANSWER: N` — номер папки из списка, который собрали мы, плюс `none`. Модель
не придумывает названий, а выбирает из готового.

**Почему проходит.** Это тот же приём, что в поиске вкладки и смысловом Ctrl+F: выбор из
списка, а не генерация. Ошибка стоит одного клика по выпадающему списку. Список папок и
заголовок страницы — личные данные.

**Почему не обычный код.** Совпадения слов тут почти не бывает: статья «Как считать неустойку»
должна попасть в папку «Работа», а рецепт — в «Дом». Это ровно семантика, и она у каждого своя.

**Где живёт.** `showBookmarkMenu()` в `main.ts` — там список папок уже собирается из
`BookmarkManager.listTree()`, то есть материал для промпта готов на месте. Гейт `isModelWarm()`
обязателен: на холодной модели меню ведёт себя ровно как сегодня.

**Объём.** Малый.

## 3. Имя файла по содержимому для загрузки ⭐

**Что.** Скачанные документы называются `document(3).pdf`, `scan_20260804.pdf`,
`vypiska.pdf`. В поповере загрузок — пункт «Назвать по содержимому», после которого файл
становится `Договор аренды — ООО Ромашка — 2026-08.pdf`.

**Форма ответа.** Одна строка, дочищается кодом (кавычки, «Название:», запрещённые в имени файла
символы, длина) — той же чисткой, что у `TabRenamer.ts`, где маленькая модель тоже нарушает
правило «только имя».

**Почему проходит.** Вход — первая страница текста, выход — строка. Ошибка видна до применения
(предлагаем имя, переименовываем по подтверждению) и отменяется переименованием обратно.
Содержимое договора, справки, выписки — самое личное, что бывает; в облако его отправить нельзя.

**Почему не обычный код.** Из PDF-метаданных осмысленное имя достаётся примерно никогда.

**Где живёт.** `FileExtract.ts` уже умеет txt/md/csv/json/docx/pdf (написан для узла-файла в
графе), `DownloadsPopoverManager.ts` уже показывает список. Новое — пункт меню и промпт.

**Объём.** Малый — обе половины уже написаны, их надо соединить.

**Риск, который надо снять сразу.** Переименование файла на диске необратимо для человека, если
он не заметил. Поэтому только по явному нажатию, только с показом нового имени до применения,
и никогда пакетно.

## 4. «Куда я это дел» — один вопрос по своим данным

**Что.** Одна строка поиска, отвечающая на вопрос «где та штука про ипотеку» разом по истории,
закладкам и загрузкам. Сегодня человек должен заранее знать, в каком из трёх мест лежит ответ.

**Форма ответа.** Номера из общего пронумерованного списка кандидатов, который собрал код
(FTS5 по истории + `LIKE` по закладкам и загрузкам). Модель только переранжирует и отсекает —
это уже работающая схема `HistorySearch.ts`, расширенная на два источника.

**Почему проходит.** Модель ничего не пишет, ошибка стоит одного лишнего пункта в выдаче,
данные насквозь личные.

**Почему не обычный код.** Код даёт кандидатов, но не различает «ипотека» и «ипотечный
калькулятор в закладках трёхлетней давности». Переранжирование — уже проверенная в проекте роль.

**Где живёт.** `HistorySearch.ts` (расширить источники), раздел `HistoryBookmarks.tsx`, где
история, закладки и загрузки уже сведены в один экран, — то есть место для этой строки уже есть.

**Объём.** Средний.

## 5. Имя для группы вкладок

**Что.** Человек создаёт группу руками (перетаскиванием, ПКМ) и получает поле для ввода имени.
Предлагаем имя по составу группы, как подпись-заготовку — правится тут же.

**Форма ответа.** Строка до 20 символов, чистится кодом.

**Почему проходит.** Ровно та работа, которую уже делает первая фаза `TabOrganizer.ts` при
автогруппировке, — только применённая к группе, собранной руками. Ошибка стоит нажатия Backspace.

**Почему не обычный код.** Домен даёт имя, только когда все вкладки с одного сайта; смешанную
группу код назвать не может.

**Где живёт.** `TabOrganizer.ts` (переиспользовать промпт первой фазы), `TabManager` — создание
группы.

**Объём.** Малый.

## 6. Поиск по настройкам фразой

**Что.** Разделов настроек стало девять, а блоков внутри — десятки. Поле поиска, которое на
«сделать шрифт крупнее» открывает «Интерфейс» и подсвечивает нужный блок.

**Форма ответа.** `ANSWER: N` — номер пункта из нашего же реестра настроек.

**Почему проходит.** Выбор из закрытого списка, ошибка — открылся не тот раздел, видно сразу.

**Почему не обычный код — и почему код всё-таки основной путь.** Поиск по ключевым словам
закрывает большую часть запросов и обязан работать без модели. Модель — ВТОРОЙ эшелон, как в
`AutofillFieldMapper.ts`: включается, только когда ключевые слова не нашли ничего. Так фича
остаётся рабочей у человека без скачанной модели.

**Где живёт.** `Settings.tsx` (`NAV_ITEMS` уже единственный источник правды о разделах).

**Объём.** Средний — основная работа тут не в модели, а в реестре настроек с ключевыми словами.

## 7. «Что изменилось с прошлого раза»

**Что.** Человек возвращается на страницу, которую уже читал (документация, вакансия, условия
тарифа, страница заказа). Строкой в поповере сайта: «Изменилась цена и срок доставки» — или
честное молчание, если изменения косметические.

**Форма ответа.** Одна строка до 100 символов либо `none`. Сам diff считает КОД, сравнивая
сохранённый в индексе истории текст визита с текущим; модель получает только различающиеся
куски и называет их одной фразой.

**Почему проходит.** Вход короткий (уже отфильтрованный diff), выход — строка. Ошибка стоит
одной неточной подписи. Данные личные: что человек читал и когда.

**Почему не обычный код.** Diff кодом получается всегда, но выглядит как «-1290 +1490» на фоне
двухсот изменившихся счётчиков и рекламных блоков. Ценность — в отсеве шума, а это семантика.

**Где живёт.** `HistoryIndexer.ts` уже хранит контент визитов, `SitePopoverManager.ts` — готовое
место показа (там уже живёт «вы это уже читали»).

**Объём.** Средний. Основная работа — не модель, а отсев шума в diff до модели.

**Честная оговорка.** Пункт стоит ниже трёх первых именно потому, что половина пользы достаётся
кодом, а половина требует, чтобы контент прошлого визита реально лежал в индексе — а он лежит
не для всех страниц.

## 8. Смысловой поиск по вкладкам ВСЕХ окон

**Что.** `TabSearch.ts` уже ищет вкладку по описанию, но в пределах окна-отправителя. С
многооконностью «где-то у меня была вкладка про налоги» чаще всего означает «в другом окне».

**Форма ответа.** Та же, что и сейчас (`ANSWER: N`), список кандидатов расширяется через
`WindowRegistry`.

**Почему проходит.** Это не новая фича, а снятие ограничения у работающей — самый дешёвый
прирост пользы в списке.

**Объём.** Малый.

## Рассмотрено и отвергнуто (чтобы не переоткрывать)

- **Детектор фишинга «бренд в тексте ≠ домену».** Формально подходит по форме ответа, но цена
  ошибки не дешёвая и не видимая: ложное «всё в порядке» — это ровно тот случай, ради которого
  фича и заводится. Такое решение не имеет права зависеть от догадки 9B.
- **Объяснение, зачем сайту камера/геолокация.** Модель будет угадывать по содержимому страницы,
  а человек прочтёт догадку как факт и на её основании выдаст разрешение. Решение про
  безопасность нельзя строить на правдоподобии.
- **Автопредложение «сохранить в закладки, похоже на статью для чтения».** Незаказанное действие
  на каждой странице. Раздражение накапливается быстрее пользы — тот же класс ошибки, что у
  системного диалога «Сохранить как» на каждый файл, который в проекте уже выпилили.
- **Автозакрытие давно не открывавшихся вкладок.** Вопрос решается обычным кодом лучше (время
  последнего обращения — точное число), а необратимое действие по догадке модели противоречит
  принципу «предлагать, а не делать».
- **Пересказ письма/переписки в почтовом веб-интерфейсе.** Прямое сравнение с облачной моделью в
  лоб на её домашней задаче — анти-критерий.
- **Умное определение действия по скопированному тексту** (трек-номер, телефон, адрес → предложить
  действие). Распознаётся регулярками надёжнее и мгновенно; модель тут проиграет коду.
- **Автоматическое раскладывание новых вкладок по существующим группам.** Действие без
  подтверждения, срабатывающее на каждой навигации; вкладка уезжает из-под руки человека.
  Приемлемая форма этого — уже сделанная кнопка «Навести порядок» с откатом.

## Как это ложится в порядок работ

Идеи 2, 3, 5 и 8 — малые, каждая переиспользует готовое и делается за один заход с живым
прогоном, как остальные срезы программы. Идея 1 — самая ценная из всех и при этом единственная,
где новая работа заметна. Идеи 4, 6 и 7 требуют подготовки кодом (реестр настроек, второй
источник кандидатов, отсев шума в diff), и модель там подключается последней.

Порядок замера для любой из них — прежний: `npm run ai-bench` с повторами, сырой ответ модели в
выводе, прогрев до первого измерения.
