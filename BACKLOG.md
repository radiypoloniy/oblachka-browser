# Oblako — BACKLOG (AI-слой)

*Живой документ. Обновлён по итогам двухдневного марафона по AI-переводчику. Фиксирует состояние, архитектурные инварианты, выбор модели и план.*

---

## 1. Что готово (AI над выделением)

Полностью рабочий генеративный AI-слой для сценария «чтение»:

- **Локальный перевод** на Qwen3.5-9B Q4_K_M (GGUF) через `node-llama-cpp`. Без облака, без API, без внешних движков.
- **Определение языка** — `franc` + фолбэк кириллицы (см. инварианты). Работает ru/en/de/fr.
- **Поповер у выделения** — отдельный короткоживущий WebContentsView поверх контента; стриминг (посегментный); закрытие по Esc / крестику / клику вне / смене вкладки / закрытии вкладки.
- **Действия по ПКМ над выделением:** «Перевести», «Пересказать проще», «Объяснить», «Краткая выжимка» (последняя — только для большого выделения, порог ~40 слов, вынесен константой).
- **Markdown-рендер** результата в поповере.
- **Эмбеддинги / сортировка вкладок** — на CPU/WASM, не тронуты, работают как прежде.

---

## 2. Архитектурные инварианты (НЕ нарушать)

Добыто болью, каждый пункт стоил времени:

- **Эмбеддинги → CPU/WASM. Qwen → GPU. Никогда оба на GPU одновременно** — Qwen занимает ~6.81 ГБ из 8 ГБ (RTX 2070 Super), места на вторую модель нет.
- **Генеративные модели — только `node-llama-cpp` / GGUF**, НЕ transformers.js. Браузерная песочница transformers.js имеет жёсткий лимit 2 ГБ на файл (`fs.readFileSync` в `oblako-model://`); fp32-ONNX EuroLLM был 6.2 ГБ и не загрузился. GGUF этого лимита не имеет.
- **Сегментация — ТОЛЬКО для перевода** (по предложениям, даёт стриминг). Осмысляющие действия (объяснить/выжимка/пересказ) берут весь текст ОДНИМ куском — сегментация их ломает (даёт бессвязный разбор каждого предложения без контекста).
- **blur НИКОГДА не использовать как механику закрытия поповера** — ложно срабатывает на инициализации WebContentsView (фокус теряется в пустоту, никто его не забирает), вызывает мгновенное самозакрытие. Только явные сигналы: Esc / крестик / mousedown из контента / события вкладок.
- **Ленивая загрузка моделей** — при первом обращении, НЕ на старте браузера (Qwen грузится ~31с, показывать индикатор). Предзагрузка тяжёлой модели на старте душит запуск.
- **`console-message` на chromeView ненадёжен** — не завязывать на него критичную логику (best-effort максимум).
- **Поповер — отдельный WebContentsView**, добавляется в `contentView` ПОСЛЕ вкладки → рендерится поверх нативно (add-order z-order, не CSS z-index).
- **Прозрачность поповера** — обязателен `view.setBackgroundColor('#00000000')` на самом view (не только CSS `background: transparent`), иначе торчит непрозрачный прямоугольник-подложка вокруг карточки.
- **Координаты выделения** — `getBoundingClientRect` через `executeJavaScript` + offset `view.getBounds()`. Для большого выделения (rect больше вьюпорта / отрицательный y) — фолбэк на координату клика ПКМ, иначе поповер уезжает за экран.
- **franc: кириллица + код bg/uk/mk → трактовать как русский.** franc путает короткий русский с болгарским/украинским; без этого фолбэка перевод русского молча ломается (уходит неверное направление).
- **Сборка/запуск:** `npm run build && npm start`. `npm run dev` НЕ работает. DevTools рендерера ненадёжен.
- **Логи:** только main stdout, ASCII-теги (кириллица в консоли = кракозябры).
- **GGUF-модели (несколько ГБ) НЕ коммитить** — держать в `.gitignore`.

## 3. Выбор модели (закрыто, не переигрывать)

Перебраны и отвергнуты — с причинами, чтобы не возвращаться:

| Модель | Вердикт |
| --- | --- |
| OPUS-MT ru↔en | Крошечная/быстрая, но качество среднее. GGUF не существует (Marian-архитектуру llama.cpp не грузит). |
| EuroLLM-1.7B | Была первым выбором (~1 ГБ). Качество слабое: «casse-tête → головной убор», «RSS-рассылка». Два провала оказались багом franc, но и без него — слабее Qwen. |
| TranslateGemma-4B | Хорошее качество, но 5.35 ГБ VRAM, минимум 4B, дала смысловую ошибку на «no rush». |
| **Qwen3.5-9B Q4_K_M** | **ПОБЕДИТЕЛЬ.** Лучшее качество (прошла оба капкана — no rush, casse-tête), ~45 tok/s (warm), влезает в 8 ГБ соло (33/33 слоя на GPU), 201 язык, thinking выключен для перевода. Единый движок под все генеративные задачи. |

- **Облако отвергнуто принципиально** — API-ключи и зависимость от чужого сервиса противоречат сути проекта.
- **Ollama / внешний движок отвергнуты** — спека требует GGUF внутри приложения (`node-llama-cpp`).
- **Скорость:** квантизация экономит ПАМЯТЬ, не время. Скорость даёт влезание в VRAM (отсутствие offload на CPU). Наблюдавшиеся 2.5–3.9 tok/s были артефактом дележа VRAM с EuroLLM, не потолком.
- **Про более лёгкий квант:** если понадобится, брать только ДИНАМИЧЕСКИЙ (unsloth UD / bartowski imatrix) — гибридная архитектура Qwen3.5 (Mamba/MoE) чувствительна к жёсткой квантизации attention-слоёв; сырой Q3 их портит. Сейчас Q4_K_M влезает — не требуется.
- **WebGPU для эмбеддингов:** корректен только на fp32 (q8 = тихий мусор cosine≈0, f16 = NaN на кириллице). Но fp32 = 1.2 ГБ ради редкой операции не окупается → эмбеддинги остаются на CPU/WASM.

## 4. BACKLOG

### 4.1. AI-хвосты (мелкие — докрутить начатое)

- [ ] **Молчаливый провал.** Поповер при ошибке / пустом результате / таймауте должен показывать «не удалось перевести», а не висеть в вечной загрузке. *(надёжность)*
- [ ] **Мультиязычность — UI.** `targetLang` уже конфигурируемый параметр с дефолтом `'ru'` и готов к настройке, но UI-переключателя нет. Подключить к неактивной кнопке настроек AI (выбор целевого языка).
- [ ] **Токен-стриминг** (плавность «как в чатботах»). Сейчас посегментный — визуально решает, но не плавный. Опциональная полировка через колбэк `node-llama-cpp`.
- [ ] **Эксперимент: перевод без сегментации.** Отложен пользователем. Гипотеза: у Qwen большой контекст, сегментация для нормальных выделений может быть не нужна и вредить связности (местоимения, «это»/«однако», единообразие терминов). Проверить сравнением. Цена: без сегментации теряется посегментный стриминг → понадобится токенный.

### 4.2. Полировка поповера (отложено)

- [ ] **Репозиционирование при ресайзе окна.** Сейчас НЕ обрабатывается — поповер остаётся на месте, может «уехать» от текста при изменении размера. Решение: либо закрывать при ресайзе (дёшево), либо динамический пересчёт (дорого).
- [ ] **Высота поповера с Markdown.** Проверить, что cap-высота и скролл корректны после рендера разметки (форматированный текст выше сырого).

### 4.3. AI над всей страницей (новый блок — следующая сессия)

*Общая техническая база: извлечение осмысленного текста страницы (статья, не меню/реклама/футер). Порядок — по возрастанию сложности.*

- [ ] **Извлечение текста страницы** + **пересказ / выжимка всей страницы** по кнопке AI в тулбаре. Среднее. Только чтение контента, DOM не переписываем. Переиспользует Qwen и осмысляющие действия. ⚠️ Длинная страница — тысячи слов, всплывёт вопрос контекста/обрезки.
- [ ] **Чат по странице** (боковая панель, «спроси о странице»). На той же извлечённой базе + AI-хаб из спеки.
- [ ] **Перевод страницы целиком.** Тяжёлое — DOM-война: заменить КАЖДЫЙ текстовый узел переводом, сохранив вёрстку/картинки/ссылки. Прир art: Bergamot / TRANSLATE! (не изобретать заново). Подходить, когда извлечение текста отлажено на пересказе.

### 4.4. AI в веб-чатах (самый тяжёлый — позже)

*Из спеки «Помощник в веб-чатах». Верхняя ступень сложности: запись в чужой сайт-специфичный DOM, хрупкость к редизайнам, только веб-версии.*

- [ ] Перевод входящих сообщений.
- [ ] Черновик ответа / смена тона / переформулировка.
- [ ] Замена текста на переведённый по клику; перевод исходящего на язык собеседника.
- ⚠️ Зависит от конкретного сайта (Telegram Web, WhatsApp Web — разный DOM), ломается при их редизайне, требует инъекции скриптов с записью.

### 4.5. Известные баги / ограничения AI

- Перевод текста с IPA/фонетической транскрипцией внутри: модель спотыкается, вставляет непереведённые обрывки (тест WoW). Краевой случай.
- Имена собственные иногда переводятся («World of Warcraft → Мир Warcraft»). Поведение модели, чинить сложно.
- `franc` на очень коротких строках (одно слово) может ошибаться. Смягчено фолбэком кириллицы, но не идеально.
