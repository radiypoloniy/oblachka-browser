# CLAUDE.md — правила работы над Oblako Browser

Этот файл читается автоматически. Соблюдай его в каждой задаче.

## Что это за проект

Oblako — приватный браузер на Electron (Chromium + Node), Windows x64, со
встроенным VPN и локальным AI. Сейчас готово только **ядро (Этап 1)**: окно,
сайдбар вкладок, тулбар, омнибокс, открытие реальных сайтов в WebContentsView.
Всё остальное (VPN, AI, пароли, усыпление, split) — впереди, по дорожной карте.

Стек: **Electron 31 + TypeScript (strict) + Vite + React 18**. Иконки — lucide-react.
UI построен на дизайн-системе Oblako (Liquid Glass) через CSS-токены.

## Архитектура — НЕ нарушать

Главный принцип: **UI браузера и веб-страницы — два разных слоя.**

- `electron/main.ts` — главный процесс: окно, IPC, внешние протоколы.
- `electron/TabManager.ts` — ВСЯ логика вкладок. Владеет WebContentsView,
  показывает/прячет, позиционирует в «дырку» под контент, парсит омнибокс,
  политика window.open, навигация. **Логика живёт здесь, не в компонентах.**
- `electron/preload.ts` — безопасный мост: типизированный `window.oblako` через
  contextBridge. Страницы изолированы (contextIsolation + sandbox, без Node).
- `shared/ipc.ts` — единый контракт типов и каналов между main и renderer.
  **Меняешь контракт — меняй обе стороны и этот файл синхронно.**
- `src/` — React-хром. Компоненты ТОЛЬКО рисуют то, что им дали, и зовут
  `window.oblako.*`. Никакой бизнес-логики вкладок в компонентах.
- `src/styles/tokens/` — токены дизайн-системы. Цвета/радиусы/тени берутся
  отсюда через `var(--...)`, **не хардкодить цвета в компонентах.**

Правило: React рисует рамку, main-процесс кладёт WebContentsView в область
контента. Renderer измеряет область (ResizeObserver) и шлёт bounds в main.

## Цветовой закон (строгий, из дизайн-системы)

- Акцент — ОДИН (сейчас `--accent`). Активные состояния, send, выделение, фокус.
- Синий (`--system`) — ТОЛЬКО облако/система. Не для ссылок и декора.
- Зелёный (`--dot-local`, `--dot-vpn`) — функционально: локальная модель / VPN жив.
- Перекраска делается подменой ЗНАЧЕНИЙ токенов в `colors.css`, не имён и не
  компонентов. Функциональные цвета (зелёный=локально, синий=облако) не трогать.

## Как писать код

- **Чистота и читаемость важнее ранней оптимизации.** Не оптимизируй вслепую.
  Оптимизация — только прицельно там, где измеримо тормозит на живых тестах.
- TypeScript strict. Не глуши ошибки через `any`/`@ts-ignore` без причины и
  комментария, почему иначе нельзя.
- Комментарии — по-русски, объясняют ЗАЧЕМ (намерение, риск), а не ЧТО.
- Не добавляй зависимости без явной нужды. Если добавляешь — скажи зачем.
- Не рефактори то, о чём не просили. Узкая задача = узкая правка.

## Ритм работы — строго

- **Одна фича за заход.** Не браться за две сразу — иначе при поломке не понять,
  что виновато.
- После изменений: собери (`npm run build`) и проверь типы ОБОИХ таргетов
  (`tsc -p tsconfig.json --noEmit` и `tsc -p electron/tsconfig.json`) ДО того,
  как сказать «готово».
- Не ломай то, что уже работает. Если правка задевает рабочую функцию —
  предупреди заранее.

## Кроссплатформенность (прицел на macOS-порт)

Проект сейчас Windows x64, но macOS-версия в планах. Чтобы порт был «дописать
слой», а не «переписать проект», ВЕСЬ платформенно-зависимый код изолируй за
интерфейсами/абстракциями, а не размазывай по проекту:
- **Хранилище секретов** (пароли, позже): абстрактный `SecretStore`, под капотом
  Windows DPAPI / macOS Keychain. Остальной код знает только интерфейс.
- **Запуск VPN/Xray**: абстракция над спавном процесса и настройкой прокси —
  реализации Windows / macOS отдельные.
- **AI-runtime / VRAM-бюджет**: учитывать, что Windows = NVIDIA/CUDA + выделенная
  VRAM, macOS = Apple Silicon/Metal + unified memory. Логика бюджета за
  платформенным интерфейсом.
- **Titlebar/окно**: Windows titleBarOverlay vs macOS trafficLight (кнопки слева).
  Раскладку шапки делать условной по платформе, не хардкодить под Windows.
Правило: если код вызывает ОС-специфичный API — он живёт за интерфейсом с
платформенными реализациями, а не инлайн в общей логике.

## Безопасность данных и стоп-условия

- ⚠️ **Сейчас НЕТ автосейва сессии.** Закрытие/краш = потеря вкладок. Это первый
  приоритет. Пока его нет — особенно осторожно с любым кодом, трогающим состояние.
- Перед изменениями, которые трогают данные на диске (автосейв, профиль, vault,
  миграция) или внешние процессы (Xray/VPN) — **предупреди о риске потери данных
  или сломанного билда** и предложи проверить на пустом профиле / сделать коммит.
- Не давай указаний и не пиши код, которые могут привести к откату прогресса,
  потере данных или сломанной сборке, без явного предупреждения.

## Дорожная карта (порядок — снизу вверх по риску)

1. **Сантехника + автосейв сессии** (текущий приоритет): автосейв вкладок,
   контекстное меню ПКМ, страницы ошибок + падение рендер-процесса, хоткеи
   (Ctrl+T/W/L, Ctrl+Shift+T, Ctrl+F, зум), навигация мышью.
2. Вкладки по-взрослому: закреплённые (переживают перезапуск), усыпление, split.
3. Приватность и адблок: webRequest + EasyList, счётчик, WebRTC.
4. VPN: Xray дочерним процессом.
5. AI: локальная модель, хаб, контекстный поповер.

## Платформа

Цель — Windows x64. Код кроссплатформенный, но titlebarOverlay и DPAPI (позже) —
Windows-специфика. Шрифты сейчас с Google Fonts; для прода забандлить локально.
