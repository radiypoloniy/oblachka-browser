# CLAUDE.md — правила работы над Oblako Browser

Этот файл читается автоматически. Соблюдай его в каждой задаче.

## Что это за проект

Oblako — приватный браузер на Electron (Chromium + Node), Windows x64, со
встроенным VPN и AI. Ядро (окно, вкладки, омнибокс, split, группы, закреп,
усыпление, автосейв сессии), сантехника (адблок, история, загрузки, разрешения
сайтов, пароли/vault) и AI (локальный инференс Qwen через `node-llama-cpp` —
перевод/пересказ/объяснение выделения, перевод страниц, AI-группировка
вкладок, боковая AI-панель с чатом; плюс облачные интеграции — AI-хаб на
новой вкладке с веб-поиском через SearXNG и фактчек через Gemini) — уже
реализованы. VPN — Xray-core дочерним процессом (импорт подписки, генерация
конфига, `session.setProxy`, fail-closed kill switch). VPN и адблок живут в карточке
под ЩИТОМ в адресной строке — отдельной пилюли «Защита» в тулбаре больше нет
(см. `electron/SitePopoverManager.ts`). Не
позиционируем браузер как «только локальный ИИ» — часть AI-функций облачная,
см. ниже. Актуальный список готового/недостающего — в README.md и в разделе
«Дорожная карта» ниже.

Стек: **Electron 40 + TypeScript (strict) + Vite + React 18**. Иконки — lucide-react.
UI построен на дизайн-системе Oblako (Liquid Glass) через CSS-токены. AI-инференс —
`node-llama-cpp` (локальная LLM Qwen) + `@mozilla/readability` (извлечение текста
страницы). Эмбеддинги/векторный поиск (`@huggingface/transformers`) испытывались
и были удалены из проекта целиком — тупиковый подход на этом корпусе, не баг (см.
`TabOrganizer.ts` и `HistorySearch.ts` ниже). Перевод страниц — движок Bergamot
(WASM/CPU, `@browsermt/bergamot-translator`, свой `worker_thread`) с фолбэком на
Qwen. История — `better-sqlite3` (нативный модуль, требует пересборки под
Electron ABI, см. `postinstall`). Артефакты «Студии» блокнота рисуют
детерминированные либы в renderer: майндкарты — `markmap-lib` + `markmap-view`
(SVG), инфографика — своя вёрстка карточек в `studioViews.tsx` (движок
`@antv/infographic` убран: его шаблоны с фиксированной шириной полей ломали
раскладку, и промптом это не лечилось); модель
отдаёт только структуру/текст (см. «Блокнот» ниже).

## Команды

```bash
npm run dev                          # Vite (5173) + Electron dev-режим одновременно
npm run build                        # vite build + tsc -p electron/tsconfig.json (прод-сборка)
                                     # перед tsc чистит осиротевшие .js в dist-electron, см. ниже
npm start                            # запуск собранного прод-приложения (dist-electron)
npm run dist                         # NSIS-установщик в release/ (без публикации)
npm run release                      # то же + выкладка релиза на GitHub (нужен GH_TOKEN)
npm run make-icon                    # build/icon.png из build/logo-source.png
npm run download-fonts               # woff2-субсеты Golos Text + JetBrains Mono в src/assets/fonts
npm run download-flags               # SVG-флаги стран для списка VPN-серверов (src/public/flags)
npm run download-browser-logos       # логотипы браузеров для экрана переноса данных (src/public/browsers)
npm run download-crypto-icons        # значки монет для виджета «Крипта» (src/public/crypto)
npm run download-filters             # (легаси) EasyList в resources/ — текущий адблок их НЕ читает
npm run download-xray                # бинарник Xray-core для VPN (electron/VpnProcess.ts)
npm run download-translation-models  # пары en<->X для Bergamot из реестра Mozilla Remote Settings
npm run bergamot-smoke               # ручная проверка перевода страниц без UI (см. README)
npm test                             # ВСЕ проверки scripts/*-check.mjs разом (см. ниже)
npm test -- word                     # только проверки, чьё имя содержит «word»
npm test -- contract                 # только сторож проводки IPC (см. ниже)
npm run bookmarks-schema-check       # прогон миграции базы закладок и API папок на временной базе
npm run filename-check               # прогон санитайзера имени файла (shared/fileNameSafety.ts)
npm run settings-search-check        # прогон реестра и поиска по настройкам (shared/settingsIndex.ts)
npm run address-parse-check          # прогон разбора вставленного адреса (shared/addressParts.ts)
npm run text-diff-check              # прогон сравнения страницы с прошлым визитом (shared/textDiff.ts)
npm run word-match-check             # прогон сопоставления слов со склонениями (shared/wordMatch.ts)
npm run calc-check                   # прогон арифметики, процента и разбора вставки калькулятора (shared/calc.ts)
npm run clipboard-order-check        # прогон порядка и вытеснения записей буфера (shared/clipboardOrder.ts)
npm run measure-model                # замер требований GGUF-модели (VRAM/RAM) до скачивания
npm run ai-bench                     # батарея замеров AI-функций на установленной модели
npm run ai-bench -- --model 4b --repeat 3   # то же на другой модели, три повтора на случай
```

Локальная LLM (GGUF, Qwen) скачивается из UI (реестр/каталог моделей —
`electron/ModelDownloader.ts` + `electron/ModelCatalog.ts` + `electron/ModelRegistry.ts` +
`electron/HardwareInfo.ts` (замер VRAM/RAM) + `src/components/ModelsSection.tsx`), отдельного
npm-скрипта для загрузки самой модели нет.

⚠️ **`tsc` только добавляет файлы и никогда не убирает.** Переименовал или удалил `.ts` — его `.js`
остаётся в `dist-electron` навсегда. Обычно это мусор, но один случай ядовитый и уже случился:
`shared/ipc.ts` стал папкой `shared/ipc/`, и рядом с новым `shared/ipc/index.js` лежал старый
`shared/ipc.js` — а CommonJS резолвит ФАЙЛ раньше ПАПКИ, то есть приложение молча продолжало бы
работать по контракту полугодовой давности, без единой ошибки. Поэтому `build:electron` и
`dev:electron` начинаются с `scripts/prune-stale-build.mjs`: убирает только `.js`/`.js.map`/`.d.ts`,
у которых больше нет исходника. Проверить, ничего не трогая: `node scripts/prune-stale-build.mjs --dry`.

Проверка типов ОБОИХ таргетов (обязательна после изменений, см. «Ритм работы»):

```bash
npx tsc -p tsconfig.json --noEmit         # renderer (src/)
npx tsc -p electron/tsconfig.json          # main-процесс (electron/)
```

Автотесты есть — `npm test` (`scripts/test.mjs`) прогоняет все `scripts/*-check.mjs`
одной командой и возвращает ненулевой код при первом же провале. Сейчас это 21
проверка и 469 ассертов: разбор адреса, санитайзер имени файла, правила, поиск по
настройкам, сопоставление слов, диффы, товарные сигналы, миграция схемы закладок,
проводка IPC-контракта, круг сессии, дерево сайдбара, индикатор паролей, склейка
скриптлетов адблока, определение языка, политика усыпления, геометрия split,
арифметика и процент калькулятора, порядок записей буфера.
`npm test -- word` гоняет только подходящие по имени.

Новая проверка подхватывается прогоном САМА — достаточно положить
`scripts/<имя>-check.mjs`, правки `test.mjs` и package.json не нужны. Конвенция:
хелпер `check(что, получили, ждали)`, счётчики passed/failed,
`process.exit(failed === 0 ? 0 : 1)` в конце. Три исторических формата итоговой
строки прогон понимает все — приводить старые проверки к одному виду не нужно.

⚠️ Тесты покрывают ЧИСТУЮ ЛОГИКУ и статику. Гонки в жизненном цикле вью, неверное
использование Electron API и вёрстка ими не ловятся — там по-прежнему `tsc` двух
таргетов и живая проверка.

Линтер есть, но свой и узкий — `conventions-check.mjs`: фиолетового нет в системных цветах,
renderer не трогает `ipcRenderer` напрямую, `any`/`@ts-ignore` объяснены комментарием, модули
`shared/` под проверками не тянут значимых импортов. ⚠️ ESLint не ставился намеренно: все четыре
правила специфичны для проекта и в ESLint потребовали бы своего плагина — тот же код плюс
зависимость и конфиг. Готовые правила (react-hooks, no-floating-promises) — отдельный разговор.
Неиспользуемый код ловит сам `tsc`: `noUnusedLocals`/`noUnusedParameters` включены в ОБОИХ
таргетах, то есть это ошибка сборки, а не предупреждение.

`contract-check.mjs` — сторож проводки IPC (359 каналов, 303 обработчика): мёртвые
каналы, `invoke` без `handle` (в рантайме «No handler registered», `tsc` этого не
видит), подписка без отправителя, арность, канал зашитый строкой мимо `IPC.*`.
Разбирает AST, приложение не поднимает. Golden-инвентарь каналов лежит в
`scripts/fixtures/ipc-channels.json`; осознанное изменение набора каналов —
`node scripts/contract-check.mjs --update`.

⚠️ `preload-content.ts` дублирует строки каналов руками и обязан это делать:
sandboxed preload (`sandbox: true` для гостевых страниц) не может `require()`
относительные модули, импорт контракта уронит все хуки на странице. Сторож сверяет
эти строки с контрактом вместо человека — правило перевёрнутое, но проверяемое.

`sleep-policy-check.mjs` — политика усыпления вкладок (`shared/sleepPolicy.ts`).
⚠️ Держит оба края: мягче — браузер не отдаёт память системе (замер против Яндекс.Браузера:
5688 МБ Working Set против 4428 при равных Private Bytes), жёстче — вкладки выгружаются по три
в минуту при десятках свободных гигабайт (живая жалоба «перекрутили выгрузку»). Давление —
КОНЪЮНКЦИЯ: мы над своим бюджетом И системе тесно на самом деле.

`split-layout-check.mjs` — геометрия split-панелей и зажим доли (`shared/layout.ts`). Проверяет
инварианты, а не числа: две панели в сумме дают всю область контента, зазор ровно `ISLAND_GAP`,
узкое окно не даёт отрицательных размеров. Плюс сверяет пределы доли с копией в `sessionTree.ts`.

`scriptlet-bundle-check.mjs` — склейка скриптлетов адблока (`shared/scriptletBundle.ts`).
⚠️ Держит ДВА взаимно противоположных требования сразу: общий скоуп (иначе два prevent-fetch из
разных копий обвязки uBO зацикливаются — chatgpt.com не открывался) и раздельные лексические
объявления (иначе четыре `json-prune` с `class JSONPath` дают SyntaxError на всю пачку — реклама
в видео YouTube не резалась вовсе). Чинить их поодиночке = ломать второе.

`lang-detect-check.mjs` — выбор языка текста (`shared/langDetect.ts`) на НАСТОЯЩИХ ответах franc.
⚠️ Три эвристики поверх ошибок franc конфликтуют между собой — правишь одну, прогоняй весь набор.

`node-tree-check.mjs` — обходы дерева сайдбара (`shared/nodeTree.ts`): поиск группы/родителя,
роспуск группы и пары, уборка пустых групп. ⚠️ Почти каждый случай проверяется дважды — на верхнем
уровне и во ВЛОЖЕННОЙ группе: ошибка «обошли только первый уровень» здесь тихая, человек видит не
сбой, а «кнопка не работает».

`session-roundtrip-check.mjs` — круг «дерево вкладок → сохранили → восстановили → то же дерево»
на чистой логике из `shared/sessionTree.ts`: вырождение split-пары при приватной половине, зажим
`ratio` из файла, опустевшие группы, вложенность, две вкладки одного адреса, инвариант «сколько
вкладок сохраняемо — столько и сериализовано». Раньше это место не проверялось ничем: логика жила
приватными методами `TabManager`, а он поднимается только вместе с приложением и боевым профилем.

Ручные диагностические скрипты в `scripts/` (в `npm test` НЕ входят, потому что
поднимают приложение): `smoke-test.mjs` — запускает прод-сборку через CDP и делает
скриншот в `scripts/shots/`; `check-dom.mjs`, `diag-hub-shadow.mjs` — точечная
диагностика вёрстки. ⚠️ Профиль они НЕ изолируют — открывается боевой `userData`
(см. «Безопасность данных и стоп-условия»). Изолированные AI-стенды запускаются
флагами окружения поверх `npm start`: `OBLAKO_GPU_TEST=1`, `OBLAKO_LLAMA_TEST=1`,
`OBLAKO_TRANSLATE_TEST=1` — открывают отдельное тестовое окно ВМЕСТО боевого
браузера (см. `electron/main.ts`).

Правило: React рисует рамку, main-процесс кладёт WebContentsView в область контента. Renderer
измеряет область (ResizeObserver) и шлёт bounds в main.

Обработчики IPC живут в `electron/ipc/*.ts` (13 файлов), `main.ts` только собирает для них контекст
(`makeIpcDeps`) и зовёт регистраторы. ⚠️ Нарезаны они НЕПРЕРЫВНЫМИ кусками, а не по доменам, и
переименовывать их «по смыслу» не надо: обработчики в исходной функции шли не доменными группами
(отслеживание товаров разорвано буфером обмена, пароли встречаются трижды), поэтому доменная
нарезка означала бы собирать файл из десятка перемежающихся фрагментов — не перенос, а
переписывание. Подробнее — в шапке `electron/ipc/deps.ts`.

## Цветовой закон (строгий, из дизайн-системы)

- Акцент — ОДИН (сейчас `--accent`). Активные состояния, send, выделение, фокус.
- Синий (`--system`) — ТОЛЬКО облако/система. Не для ссылок и декора.
- Зелёный (`--dot-local`, `--dot-vpn`) — функционально: локальная модель / VPN жив.
- Перекраска делается подменой ЗНАЧЕНИЙ токенов в `colors.css`, не имён и не
  компонентов. Функциональные цвета (зелёный=локально, синий=облако) не трогать.
- Палитры (`palettes.css`) — исключение только по ЗЕМЛЕ: фон, поверхности, разделители, текст.
  Акцент и функциональные цвета палитра не переопределяет ни в одной из них.
- **Фиолетового в системе нет вообще** — ни токена, ни литерала. Спека дизайн-системы не
  содержит ни одного фиолетового/розового токена (см. шапку `colors.css`), но сиреневый уже
  дважды просачивался обратно через значки: `--tile-purple`/`--tile-indigo` красили «Интерфейс»
  и «AI» в настройках, тип «картинка» и «код» в загрузках, плюс литерал `#AF52DE` у глифа
  «Цвета» и сиреневая ступень в `--appicon-color`. Убрано; вместо них `--tile-red`,
  `--tile-brown`, `--tile-slate`. Если понадобится ещё один цвет значка — брать из этого
  набора, а не «добавить фиолетовый, он тут подходит».
  ⚠️ Правило распространяется и на СГЕНЕРИРОВАННЫЙ цвет. Подложка под иконку сайта на столе
  выводилась из домена как `hash % 360`, то есть раздавала весь круг вместе с сиреневым
  сектором: `translate.yandex.ru` попадал ровно на 272°, `t.me` — на 282°. Значок сайта при
  этом прозрачный, и весь квадрат светил нашим фиолетовым, хотя у сайта его в логотипе нет.
  Теперь оттенок берётся из фиксированного набора — `src/components/desktop/siteTint.ts`,
  один на `SiteIcon.tsx` и на плитку-фолбэк в `widgets.tsx`.

## Как писать код

- **Чистота и читаемость важнее ранней оптимизации.** Не оптимизируй вслепую.
  Оптимизация — только прицельно там, где измеримо тормозит на живых тестах.
- TypeScript strict. Не глуши ошибки через `any`/`@ts-ignore` без причины и
  комментария, почему иначе нельзя.
- Комментарии — по-русски, объясняют ЗАЧЕМ (намерение, риск), а не ЧТО.
- Не добавляй зависимости без явной нужды. Если добавляешь — скажи зачем.
- Не рефактори то, о чём не просили. Узкая задача = узкая правка.

## Ритм работы — строго

- **Одна фича за заход.** Не браться за две сразу — иначе при поломке не понять,
  что виновато.
- После изменений: собери (`npm run build`), проверь типы ОБОИХ таргетов
  (`tsc -p tsconfig.json --noEmit` и `tsc -p electron/tsconfig.json`) и прогони
  `npm test` ДО того, как сказать «готово». Прогон занимает ~1 секунду — повода
  его пропускать нет.
- Правишь чистую логику в `shared/` — добавь случай в соответствующий
  `scripts/*-check.mjs` (или заведи новый, он подхватится сам). Особенно если
  правка чинит баг: случай из жизни в проверке дороже трёх выдуманных.
- Не ломай то, что уже работает. Если правка задевает рабочую функцию —
  предупреди заранее.

## Кроссплатформенность (прицел на macOS-порт)

Проект сейчас Windows x64, но macOS-версия в планах. Чтобы порт был «дописать
слой», а не «переписать проект», ВЕСЬ платформенно-зависимый код изолируй за
интерфейсами/абстракциями, а не размазывай по проекту:
- **Хранилище секретов** (пароли/vault, ключи Gemini): уже кроссплатформенно —
  `electron/VaultCrypto.ts`/`AiKeyStore.ts` заворачивают через Electron
  `safeStorage` (DPAPI на Windows, Keychain на macOS из коробки), отдельный
  `SecretStore`-интерфейс не потребовался. Остальной код не завязан на
  конкретный механизм шифрования.
- **Запуск VPN/Xray**: абстракция над спавном процесса и настройкой прокси —
  реализации Windows / macOS отдельные.
- **AI-runtime / VRAM-бюджет**: учитывать, что Windows = NVIDIA/CUDA + выделенная
  VRAM, macOS = Apple Silicon/Metal + unified memory. Логика бюджета за
  платформенным интерфейсом.
- **Titlebar/окно**: Windows titleBarOverlay vs macOS trafficLight (кнопки слева).
  Раскладку шапки делать условной по платформе, не хардкодить под Windows.
Правило: если код вызывает ОС-специфичный API — он живёт за интерфейсом с
платформенными реализациями, а не инлайн в общей логике.

## Безопасность данных и стоп-условия

- Автосейв сессии (`electron/SessionManager.ts`) есть и синхронно пишет
  `session.json` в `win.on('close')`, но формат версионирован (сейчас **v5**, типы —
  в `shared/session.ts`) и хранит реальные пользовательские данные (открытые
  вкладки/группы). Ломка формата или гонка в моменте сохранения/восстановления =
  потеря вкладок пользователя — трогать этот код особенно осторожно.
  Раскладку дерева при сохранении и восстановлении держит `shared/sessionTree.ts` —
  чистая логика под `npm test -- session`; правишь её — дописывай случай туда же.
  ⚠️ В `sessionTree.ts` не должно быть ЗНАЧИМЫХ импортов, только типовые: проверка гоняется
  голым node, а он требует расширения в пути импорта, которое `tsc` с эмитом не примет.
- Перед изменениями, которые трогают данные на диске (автосейв, история в
  `better-sqlite3`, профиль, vault, миграция формата) или внешние процессы
  (будущий Xray/VPN) — **предупреди о риске потери данных или сломанного
  билда** и предложи проверить на пустом профиле / сделать коммит.
- Не давай указаний и не пиши код, которые могут привести к откату прогресса,
  потере данных или сломанной сборке, без явного предупреждения.
- ⚠️ **Диагностика идёт на БОЕВОМ профиле.** Скрипты из `scripts/` и разовые
  проверки через CDP запускают собранное приложение, а оно открывает настоящий
  `userData` пользователя — с его историей, закладками, графами и сессией.
  Никогда не начинать проверку с очистки существующих данных: создавать своё и
  удалять ТОЛЬКО созданное. Живой случай: проверки узлов графа начинались со
  строки, снимающей все воркспейсы, и стёрли пользовательские холсты.

## Принцип AI в Oblako — «незаметный ИИ»

⚠️ **Это главный фильтр для любой AI-идеи в проекте, читать до критерия пригодности ниже.**
Oblako не делает ассистента-собеседника и не делает агента, который действует за человека. Мы
делаем **незаметный ИИ, который снимает рутину и предлагает решения**, а нажимает и подтверждает
человек. Три следствия, каждое уже оплачено работой:
- **Предлагать, а не делать.** Правило рождается из фразы, но заводится карточкой подтверждения;
  группировка предлагается кнопкой «Навести порядок» и откатывается одним движением; смысловой
  поиск подсвечивает место на странице, а не пересказывает его своими словами.
- **Не лезть в чувствительные зоны.** Никаких действий от имени человека на чужих сайтах,
  никакой автоматизации переписки и оплат, никаких необратимых действий по догадке модели.
  Каталог правил закрыт и мал именно поэтому. Отдельно см. разбор prompt injection: в агентных
  браузерах (Comet, Atlas) он в принципе не чинится, потому что агент работает с полными правами
  залогиненного человека — мы такой конструкции избегаем by design.
- **Не соревноваться с облаком там, где проиграем.** Написать текст, поспорить, поработать
  «вторым мозгом» человек пойдёт в ChatGPT или Claude, и это нормально: отказываться от них ради
  приватности никто не станет. Наша территория — то, чего облако не может в принципе, потому что
  у него нет доступа к вашим вкладкам, истории и черновикам.
