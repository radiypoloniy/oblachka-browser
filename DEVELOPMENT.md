# Oblako Browser — разработка

Техническая документация для тех, кто собирает и правит проект. Продуктовое
описание — в [README.md](README.md), карта модулей и правила работы — в
[CLAUDE.md](CLAUDE.md).

Приватный браузер на **Electron + TypeScript + Vite + React** для Windows x64:
встроенный VPN, локальный AI и обычная браузерная сантехника без телеметрии.

Ядро (вкладки, омнибокс, split view, группы, закреп, усыпление, автосейв сессии),
блокировка рекламы, история с полнотекстовым поиском, менеджер паролей, VPN
через Xray-core и AI-функции уже работают. Часть AI локальная (Qwen через
`node-llama-cpp`), часть облачная — см. «Про AI» ниже.

## Быстрый старт

Нужен **Node.js 18+** и интернет (зависимости + бинарник Electron).

```bash
npm install     # зависимости, пересборка better-sqlite3 под ABI Electron, патч Bergamot
npm run dev     # Vite (5173) + Electron в dev-режиме, с горячей перезагрузкой
```

Для итераций по интерфейсу используйте именно `npm run dev` — пересобирать
ничего не нужно. Прод-путь проверяется отдельно:

```bash
npm run build   # vite build (renderer) + tsc (electron), ~12 с
npm start       # запуск собранного приложения
```

Установщик:

```bash
npm run dist    # NSIS-установщик в release/, без публикации
npm run release # то же + выкладка релиза на GitHub (нужен GH_TOKEN)
```

> ⚠️ Если `npm install` падает на скачивании бинарника Electron (403/таймаут) —
> это сетевое ограничение окружения, не код. Поставьте зависимости там, где
> доступен `github.com` / `objects.githubusercontent.com`, либо настройте
> `ELECTRON_MIRROR`.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Vite + Electron, горячая перезагрузка |
| `npm run build` | Прод-сборка renderer + main |
| `npm start` | Запуск собранной сборки |
| `npm run dist` | NSIS-установщик в `release/` |
| `npm run release` | Установщик + публикация релиза на GitHub |
| `npm run make-icon` | `build/icon.png` из `build/logo-source.png` |
| `npm run download-xray` | Бинарник Xray-core для VPN |
| `npm run download-translation-models` | Модели Bergamot из реестра Mozilla |
| `npm run bergamot-smoke` | Проверка перевода без UI |
| `npm run measure-model` | Замер требований GGUF-модели до скачивания |

Проверка типов обоих таргетов (обязательна перед коммитом):

```bash
npx tsc -p tsconfig.json --noEmit      # renderer
npx tsc -p electron/tsconfig.json      # main
```

Автотестов и линтера в проекте нет. Есть ручные диагностические скрипты в
`scripts/` и изолированные AI-стенды за флагами окружения (`OBLAKO_GPU_TEST=1`,
`OBLAKO_LLAMA_TEST=1`, `OBLAKO_TRANSLATE_TEST=1` поверх `npm start`).

## Архитектура

Главный принцип: **UI браузера и веб-страницы — два разных слоя.** React рисует
рамку, main-процесс кладёт `WebContentsView` в размеченную ею область.

- `electron/main.ts` — окно, chrome-`WebContentsView`, регистрация всего IPC.
- `electron/TabManager.ts` — вся логика вкладок: позиционирование, split, группы,
  закреп, усыпление, парсинг омнибокса, политика `window.open`.
- `electron/preload.ts` — типизированный `window.oblako` через `contextBridge`.
  Страницы изолированы: `contextIsolation`, `sandbox`, без Node.
- `shared/ipc.ts` — единый контракт каналов и типов. **Меняете контракт — меняете
  обе стороны и этот файл синхронно.**
- `src/App.tsx` — корень хрома, меряет область контента и шлёт bounds в main.
- `src/styles/tokens/` — токены дизайн-системы (Liquid Glass). Цвета берутся
  отсюда через `var(--…)`, не хардкодятся.

Поповеры и оверлеи (AI-панель, поиск по странице, поповеры паролей/VPN/перевода,
дропдаун подсказок) — каждый в своей `WebContentsView` со своим preload и своей
точкой входа в `vite.config.ts`.

Подробная карта модулей — в `CLAUDE.md`.

## Возможности

**Вкладки и окно.** Вертикальный сайдбар, drag-and-drop, группы, закреплённые
вкладки, split view, усыпление, автосейв сессии, режим инкогнито (in-memory
сессия, без записи в историю).

**Приватность.** Блокировка рекламы на движке Ghostery (prebuilt, автообновление
листов раз в 3 дня), VPN через Xray-core дочерним процессом с fail-closed
kill switch, менеджер паролей с шифрованием AES-256-GCM поверх `safeStorage`,
автозаполнение адресов и карт (номер карты — под Windows Hello).

**Омнибокс.** Живые подсказки, история с ранжированием по frecency и **бэнги** —
`!yt котики` уводит запрос сразу на YouTube. Бэнг можно ставить и в конце
(`котики !yt`), а `!ключ` без запроса открывает главную сайта. Свой бэнг для
любого сайта добавляется без возни с URL: откройте сайт, выполните на нём поиск,
затем Настройки → Браузер → Бэнги → «Распознать» — браузер сам составит шаблон
по адресу результатов. По кнопке можно доложить готовый набор DuckDuckGo
(~13 000 записей качается в профиль, в приложение не входит).

**Данные.** История на `better-sqlite3` с полнотекстовым поиском (FTS5 +
переранжирование локальной моделью), закладки, загрузки, разрешения сайтов,
импорт закладок/истории/паролей из Chrome, Edge, Brave, Яндекс.Браузера, Opera
и Vivaldi.

**Обновления.** Через `electron-updater`: браузер тихо проверяет версию при
запуске, но загрузка и установка — только по явной команде пользователя
(см. ограничение про подпись кода ниже).

## Про AI

Не «только локальный ИИ» — часть функций облачная, и это честно указано в
интерфейсе:

- **Локально** (Qwen через `node-llama-cpp`, GGUF-модель качается из UI в профиль
  пользователя): перевод, пересказ и объяснение выделенного текста, правка
  своего текста прямо в поле ввода (ошибки/короче/тон, Ctrl+Z возвращает ваш
  вариант), перевод страниц с фолбэком на Qwen, AI-группировка вкладок, боковая
  панель с чатом, переранжирование выдачи в поиске по истории, поиск вкладки по
  смыслу в омнибоксе, «вы это уже читали» и итоги дня по своей истории.
- **Смысловой поиск по странице** — второй режим Ctrl+F: спрашиваете словами
  («где тут про возврат денег»), браузер подсвечивает нужный абзац. Модель не
  пишет ответ, а выбирает фрагмент из собранных со страницы — цитата всегда
  настоящая, поэтому её и удаётся подсветить.
**Правила-автоматизации** (раздел «Правила» в настройках) — браузер сам
раскладывает вкладки по группам, закрепляет нужные, выключает адблок или
включает VPN на выбранных сайтах. Правило собирается формой из четырёх полей и
выполняется обычным кодом; модель для этого не нужна и не запускается. Если
быстрее сказать словами — рядом есть поле фразы («ссылки с habr.com открывай в
группе Чтение»): локальная модель разберёт её и покажет карточкой, что поняла,
до того как правило будет создано.
- **Облачно**: веб-поиск через SearXNG и фактчек через Gemini API — обе функции
  требуют своих ключей и включаются пользователем вручную.

**Блокнот** (NotebookLM-подобный экран на новой вкладке): источники с извлечением
текста, заземлённый на них чат и «Студия» — саммари, майндкарта, инфографика и
интерактивный тест. Модель отдаёт только структуру и текст, рендер
детерминированный (`markmap`, `@antv/infographic`).

## Перевод страниц: Bergamot

Дефолтный движок полностраничного перевода — Bergamot (Marian NMT, WASM/CPU),
специально лёгкий для процессора в отличие от Qwen, которому нужен GPU. Живёт в
изолированном сервисе (`electron/BergamotService.ts` + `BergamotWorkerEntry.ts`)
в собственном `worker_threads.Worker`, не в renderer. Если для пары языков модели
нет, `TranslationEngineRegistry` тихо откатывается на Qwen.

### Патч пакета (делается автоматически из `postinstall`)

`@browsermt/bergamot-translator` опубликован в 2022 и с тех пор не обновлялся —
в Node на Windows он не работает из коробки. `scripts/patch-bergamot.mjs`
(идемпотентен) чинит три реальных бага, найденных живым прогоном:

1. `worker/translator-worker.js` наследует `"type":"module"` от пакета, но его же
   Node-совместимый слой зовёт голый `require(...)` — под ESM это `ReferenceError`.
   Фикс: `worker/package.json` с `{"type":"commonjs"}`.
2. `self.location` строился как `` new URL(`file://${__filename}`) `` — на Windows
   путь с бэкслешами и буквой диска не парсится как валидный URL.
   Фикс: `pathToFileURL(__filename)`.
3. Та же болезнь в `self.fetch()` для `file://`: читался `url.pathname`
   (`/C:/Users/…` буквально как путь) → `ENOENT` вида `open 'C:\C:\Users\…'`.
   Фикс: `fileURLToPath(url)`.

Если версия пакета сменится и патч перестанет находить нужные строки, скрипт
явно упадёт с понятным сообщением, а не пропустит фикс молча.

### Модели

```bash
npm run download-translation-models
```

Качает пары `en<->X` из реестра Mozilla Remote Settings (боевой CDN Firefox
Translations) в `resources/models/translation/{from}-{to}/` — каталог в
`.gitignore`. Версия не зафиксирована: скрипт берёт свежайшую, у которой есть
полный комплект файлов. Не для всех языков есть модель в обе стороны (`be` —
только `be->en`) или вообще (`zh` — нет записей); скрипт логирует такие случаи
и не падает.

Приоритет чтения: `{userData}/models/translation/`, при пустоте — фолбэк на
бандл. Копировать файлы вручную не нужно.

### Ручная проверка без UI

```bash
npm run build:electron
npm run bergamot-smoke -- --from en --to ru --text "<p>Hello <b>world</b></p>"
```

Инлайновая разметка переносится через выравнивание, а не поиск-замену: `<b>` и
`<a href=…>` остаются на переведённых словах.

## Известные ограничения

**Сборка не подписана.** Это главный блокер распространения, а не косметика:

- **Smart App Control** (включён по умолчанию на чистых Windows 11) блокирует
  установщик наглухо, без кнопки обхода. Отключается только необратимо — обратно
  включить нельзя без переустановки системы.
- **SmartScreen** предупреждает при каждой установке.
- **Автообновление** упрётся в тот же барьер: `electron-updater` скачает
  обновление, но система не даст его установить.

Поля подписи в `electron-builder.yml` заранее не заданы — добавить
`win.certificateFile`/`certificateSubjectName` и `publisherName`, когда появится
сертификат. Оговорка: подпись необходима, но не мгновенно достаточна — Smart App
Control учитывает ещё и репутацию издателя, которая нарабатывается со временем.

**Установщик крупный** (~290 МБ): около 310 МБ занимают бэкенды `node-llama-cpp`
для CPU, CUDA и Vulkan. Сборки под чужое железо (`win-arm64`) и аварийный
CUDA-фолбэк (`win-x64-cuda-ext`, 361 МБ) исключены осознанно.

**Шрифты** (`Golos Text`, `JetBrains Mono`) вшиты в приложение: субсеты woff2
лежат в `src/assets/fonts` (147 КБ, оба под SIL OFL 1.1, тексты лицензий там же),
`@font-face` — в `tokens/fonts.css`. Сети не требуют и о запуске браузера гуглу
не сообщают. Обновление — `npm run download-fonts`. У Golos Text ось веса
400–700, светлого начертания нет: `--fw-light: 300` браузер поджимает к 400.

**Vision для Qwen отложен**: `node-llama-cpp` не выставляет мультимодальность в
свой API ни в установленной версии, ни в последней доступной — сама llama.cpp это
давно умеет, но связка с Node нет. Вернуться при обновлении библиотеки.

**macOS-порт в планах.** Платформенно-зависимый код (секреты, спавн VPN,
VRAM-бюджет, титлбар) изолирован за интерфейсами, чтобы порт был «дописать слой»,
а не «переписать проект».

## Данные пользователя

Профиль живёт в `app.getPath('userData')`
(`%APPDATA%\oblako-browser\` на Windows) — вне папки проекта. Там же пароли
(`passwords.sqlite`), история (`history.sqlite`), сессия (`session.json`),
скачанные модели и ключи API. Секреты шифруются через Electron `safeStorage`
(DPAPI на Windows), plaintext на диск не пишется.

Автосейв сессии версионирован и пишется синхронно при закрытии окна. Правки,
затрагивающие формат сохранения, требуют особой осторожности — это реальные
вкладки пользователя.
