# Слой команд — архитектура

> Выдержка из CLAUDE.md. Читать ПЕРЕД правкой в этой области: единица «команда», реестр, конвейер
> выполнения, права, предпросмотр, откат, двери вызова. Презентация идеи и обоснование —
> артефакт «Команды Oblako»; здесь только устройство.

Команда — **именованное намерение с объявленными правами**. Не агент: она не нажимает за человека
и не имеет права на действие, которого нельзя отменить.

Три вида, и различает их не интерфейс, а права: **ответ** (ничего не меняет), **действие**
(меняет состояние, значит обязателен предпросмотр и откат), **правило** (то же действие, но по
событию). Существующие Правила — это уже третий вид, просто живут отдельно.

## 1. Модель данных — `shared/commands.ts`

Чистые данные и проверки, без импортов electron: файл нужен main (исполнение), renderer (экран
команд и омнибокс) и разборщику фразы, и его прогоняет голый node. ⚠️ Значимых импортов быть не
должно — то же ограничение, что у `shared/rules.ts` и `shared/sessionTree.ts` (см. CLAUDE.md).

```ts
export type ContextKey = 'page' | 'selection' | 'tabs' | 'history' | 'notebook' | 'downloads';
export type ToolId =
  | 'tabs.group' | 'tabs.close' | 'tabs.open'
  | 'notebook.write' | 'autofill.fill' | 'tracking.watch' | 'rules.create';
export type DoorKind = 'omnibox' | 'selection' | 'event';

export interface CommandDef {
  id: string;
  name: string;          // «Разобрать вкладки» — то, что видно в списке
  phrase: string;        // формулировка человека; объясняет, ЗАЧЕМ команда заведена
  prompt: string;        // что уходит модели (у встроенных — наш текст)
  builtin: boolean;
  needs: ContextKey[];   // что команде разрешено ВИДЕТЬ
  tools: ToolId[];       // что ей разрешено ДЕЛАТЬ; пустой массив = команда-ответ
  doors: DoorKind[];     // откуда вызывается
  trigger?: RuleTrigger; // только при door 'event' — тип берём из shared/rules.ts
  createdAt: number;
  lastRunAt: number;
  runs: number;
}
```

⚠️ **`needs` и `tools` — ЗАКРЫТЫЕ перечисления, и это граница доверия, а не типизация для
удобства.** Ровно тот же приём, что уже держит правила: `validateCommand()` принимает только
перечисленное, ответ модели проходит через неё целиком, поэтому «модель придумала своё действие»
физически не может стать командой. Расширять каталог можно, но каждый новый пункт — отдельное
решение с ответом на вопрос «как это отменить».

⚠️ **`runs` и `lastRunAt` живут в определении команды, а не в отдельной статистике.** Список
команд — единственное место в браузере, которое зарастает по вине самого человека, и он обязан сам
показывать, что пора выбросить.

## 2. Реестр — `electron/CommandStore.ts`

Устройство копирует `SkillsStore.ts`: свой файл `commands.json` в `userData`, атомарная запись
(`.tmp` + rename), слушатели изменений, потолок числа записей.

**Миграция навыков.** Существующие `skills.json` переезжают на первом запуске: скилл становится
командой с `needs: ['page']`, `tools: []`, `doors: ['omnibox', 'selection']`. Формулировка скилла
становится `prompt`, подпись — `name`.

⚠️ **Правила НЕ сливаются в один файл с командами**, хотя по смыслу это один слой. У правил своя
схема на диске, свой сторож и свой экран, а слияние означало бы миграцию пользовательских данных
ради красоты модели. `CommandStore` отдаёт правила ТОЛЬКО представлением (read-only view поверх
`RuleStore`), и редактируются они там же, где и раньше.

## 3. Конвейер — `electron/CommandEngine.ts`

Семь шагов, один и тот же порядок для всех команд без исключения:

| Шаг | Что делает | Где живёт |
| --- | --- | --- |
| `resolve` | фраза → кандидаты команд | **локально, без модели** (см. §6) |
| `collect` | сбор контекста по `needs` | `ContextCollector` |
| `run` | обращение к модели, полоса `user` | `QwenQueue` |
| `preview` | типизированный результат | push в chrome |
| `confirm` | нажимает человек | карточка результата |
| `apply` | вызов инструментов | `ToolRegistry` |
| `undo` | откат по токену | тот же инструмент |

⚠️ **`apply` вызывается ТОЛЬКО из обработчика подтверждения.** Движок не имеет права звать
инструменты сам ни при каких условиях — это единственное место в коде, где различаются
«предложить» и «сделать», и оно должно быть одной строкой, а не рассуждением.

⚠️ **Запуск — не `invoke` с ожиданием ответа.** Модель думает секунды, а окно обязано остаться
живым: `COMMAND_RUN` возвращает `runId` немедленно, результат приезжает push'ом — тем же приёмом,
что прогресс скачивания модели.

## 4. Предпросмотр — типизированный, а не текст

```ts
export type CommandPreview =
  | { kind: 'text'; text: string }                                   // ответ
  | { kind: 'list'; rows: { label: string; sub?: string; verdict: string; checked: boolean }[] }
  | { kind: 'fields'; fields: { label: string; value: string }[] }   // форма
  | { kind: 'diff'; before: string; after: string }                  // заметка, страница
  | { kind: 'rule'; rule: AutomationRule };                          // «каждый раз, когда…»
```

⚠️ **Тип обязателен, свободного текста модели в карточке нет.** Две причины, и обе несущие.
Первая: человек утверждает СПИСОК, а не абзац — снять галочку с одной строки он может только там,
где строки есть. Вторая: это защита от инъекции — модель, которой скормили чужую страницу, не
может «нарисовать кнопку» или подделать вопрос, потому что рисует карточку наш код по нашей схеме.

## 5. Инструменты — `electron/CommandTools.ts`

```ts
export interface Tool {
  id: ToolId;
  needs: ContextKey[];
  apply(input: unknown): Promise<UndoToken>;   // null возвращать нельзя
  undo(token: UndoToken): Promise<void>;
}
```

⚠️ **Нет отката — инструмента не существует.** `registerTool()` отказывает регистрировать
инструмент без `undo`; правило из презентации становится проверкой в коде, а не договорённостью.

Первые шесть — все стоят на готовом:

| Инструмент | На чём стоит | Откат |
| --- | --- | --- |
| `tabs.group` | `TabManager`, снимок `organizeSnapshot` | снимок дерева до применения |
| `tabs.close` | `TabManager.closedTabs` (стек Ctrl+Shift+T) | восстановление адресов |
| `tabs.open` | `TabManager.createTab` | закрыть открытое |
| `notebook.write` | `GraphStore` версии узлов | предыдущая версия |
| `autofill.fill` | `AutofillManager` + `sendAutofillFill` | значения полей до подстановки |
| `tracking.watch` | `TrackingStore` | снять отслеживание |
| `rules.create` | `RuleStore` | удалить правило |

## 6. Двери вызова

**Омнибокс — главная.** `SuggestKind` (см. `shared/ipc/omnibox.ts`) получает вид `'command'`,
секция «Сделать» встаёт первой, ветка Enter добавляется в `Toolbar.tsx` рядом с существующими.

⚠️ **Резолв на каждый символ идёт ЛОКАЛЬНО — по имени и фразе команды, без модели.** Модель
включается только ПОСЛЕ Enter. Иначе каждый набранный символ греет очередь генерации, а строка
адреса перестаёт отвечать мгновенно — то есть ломается ровно то, чем человек пользуется каждый
день. Порядок выбора остаётся ПЛОСКИМ и принадлежит омнибоксу (там же разбор в `omnibox.ts`).

⚠️ **Дверь в омнибоксе ВЫКЛЮЧАЕМАЯ, и это часть архитектуры, а не уступка.** Адресная строка —
самый обжитой элемент браузера; человек, которому новая сущность в ней мешает, не должен выбирать
между «терпеть» и «остаться без команд». Настройка из ТРЁХ состояний, а не тумблер:

| Состояние | Что происходит |
| --- | --- |
| `always` (по умолчанию) | команды предлагаются по обычной фразе, секция «Сделать» первая |
| `slash` | только по явному префиксу `/`; обычный ввод адресную строку не трогает вовсе |
| `off` | секции нет; команды живут в выделении, по событию и на своём экране |

⚠️ Выключатель гасит **одну дверь, а не функцию**: `off` не удаляет команды и не отключает
правила. Второе следствие — уровень команды: `doors` в `CommandDef` позволяет убрать из омнибокса
одну надоевшую команду, не трогая остальные, и настройка выше — это тот же выбор оптом.

⚠️ Даже в состоянии `always` команда встаёт первой строкой ТОЛЬКО при уверенном совпадении с
именем или фразой. Похоже на адрес или запрос — команда уходит ниже поиска. Перехватывать Enter в
адресной строке по догадке нельзя: цена ошибки здесь — «браузер не открыл сайт», а это худшее, что
может случиться с браузером.

**Выделение.** Поповер выделения показывает команды, у которых `needs` содержит `'selection'`.
Перевод и пересказ остаются на месте — они просто становятся первыми в списке.

**Событие.** `RuleEngine` как есть; команда с `door: 'event'` заводит правило через `rules.create`.

## 7. Контекст и приватность — `electron/ContextCollector.ts`

Единственное место, где читаются данные человека. По одной функции на ключ, у каждой свой лимит
объёма.

⚠️ **Инкогнито исключён целиком**, поля паролей не собираются никогда, `history` отдаёт заголовки
и адреса, но не содержимое страниц.

⚠️ **Страница — МАТЕРИАЛ, а не инструкция.** Собранный текст уходит модели в явно помеченном
блоке, промпт прямо запрещает исполнять найденное внутри. Но держит границу не промпт: ответ
модели всё равно проходит `validateCommand`/`validateAction`, поэтому инъекция способна испортить
ТЕКСТ ответа и не способна выбрать действие. Это и есть разница с агентными браузерами, где
инъекция не чинится в принципе (см. CLAUDE.md, «Принцип AI в Oblako»).

## 8. IPC

| Канал | Направление | Смысл |
| --- | --- | --- |
| `COMMANDS_LIST` / `_ADD` / `_UPDATE` / `_REMOVE` | renderer → main | реестр |
| `COMMANDS_CHANGED` | main → renderer | push после мутации |
| `COMMAND_RESOLVE` | renderer → main | фраза → кандидаты (локально, быстро) |
| `COMMAND_RUN` | renderer → main | запуск → `runId` |
| `COMMAND_PREVIEW` | main → chrome | результат прогона |
| `COMMAND_APPLY` / `COMMAND_UNDO` | renderer → main | подтверждение и откат |

## 9. Очередь к модели

Команда, вызванная человеком, — полоса `user`; правило по событию — `background` (см.
`QwenQueue.ts`).

⚠️ **Холодная модель обязана сказать о себе.** Первый прогон после запуска грузит гигабайты в
память; молчать 30 секунд нельзя — карточка показывает «модель греется», как это уже сделано в
других местах.

## 10. Что проверяется машиной

Новый `scripts/commands-check.mjs` (подхватится `npm test` сам):

- `validateCommand` отвергает выдуманные `needs`/`tools` — граница доверия;
- у каждого инструмента объявлен откат;
- `needs` команды покрывают `needs` всех её инструментов (команда не может заполнить форму, не
  имея права видеть страницу);
- миграция `skills.json` → команды не теряет ни одной записи и не даёт прав, которых у скилла не
  было.

## 11. Этап 1 — нарезка на коммиты

1. `shared/commands.ts` + `scripts/commands-check.mjs` — модель и границы, без единого вызова.
2. `CommandStore` + миграция навыков (данные на диске — коммит отдельно, чтобы откат был чистым).
3. `CommandEngine`: `resolve` + `collect` + `run` только для команд-ответов, `tools: []`.
4. Омнибокс: секция «Сделать», ветка Enter.
5. Карточка результата с предпросмотром (переиспользует существующий поповер).
6. Настройки → «Команды»: список, права, счётчики, удаление и переключатель двери в омнибоксе
   (`always` / `slash` / `off`) — вместе с самой дверью, а не «когда-нибудь потом».

Инструменты и откат — этап 3, и раньше карточки предпросмотра они не появляются: инструменты без
предпросмотра — это уже агент.

## 12. Чего в архитектуре нет намеренно

- **Чата как интерфейса.** Команда — единица работы, а не реплика; переписка живёт в ИИ-панели и
  остаётся отдельной вещью.
- **Произвольного кода в команде.** Ни скриптов, ни пользовательского JS: каталог инструментов
  закрыт именно поэтому.
- **Облачных инструментов по умолчанию.** Всё, что перечислено, работает на локальной модели;
  облако — явная кнопка человека, как в хабе.
- **Композиции команд до этапа 4.** «Команда из команд» требует отката ЦЕПОЧКИ, а это отдельная
  задача, а не следствие.
