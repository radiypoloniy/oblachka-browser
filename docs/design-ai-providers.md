# Подключение моделей: слой провайдера и его лицо

> Читать ПЕРЕД правкой в `electron/ai/`, `shared/aiRouting.ts` и в блоке «Модели» раздела настроек
> AI. Стратегия и обоснование фаз — в рабочей карте захода; здесь только устройство и вёрстка.

## 0. Две части, и почему граница проходит именно здесь

Работа делится на **незаметную (1A)** и **видимую (1B)**, и это не условное деление ради этапов:
у частей разный критерий готовности.

- **1A — слой провайдера без единой кнопки.** Критерий приёмки парадоксальный и очень удобный:
  **ничего не должно измениться.** Локальная Qwen становится одним из провайдеров, все 13 функций
  идут через новый слой, человек не видит разницы. Такой заход проверяется существующими
  прогонами: если `npm run drive` зелёный и панель отвечает как вчера — рефакторинг удался.
- **1B — маршруты, ключи и лицо.** Здесь появляются экраны, выбор и цена ошибки в UX.

⚠️ **MCP-сервер от этого слоя НЕ зависит.** Он отдаёт наружу вкладки, историю и текст страницы —
модель ему не нужна вовсе. То есть порядок «провайдер → MCP» выбран не техникой, а тем, что 1A
дешевеет от того, что делается раньше: каждый новый вызов модели, написанный до слоя, — это ещё
одно место, которое потом придётся переносить руками. Сейчас таких мест 13, и все они собраны в
одном файле.

# Часть 1A — незаметная

## 1.1. Куда что ложится

```
electron/ai/
  Provider.ts              интерфейс + типы возможностей
  registry.ts              какие подключения заведены, кто сейчас отвечает за роль
  structured.ts            «дай объект по схеме» — четыре стратегии, см. 1.3
  KeyStore.ts              ключи по провайдерам (обобщение AiKeyStore)
  providers/
    local.ts               обёртка над InferenceHost — Qwen как обычный провайдер
    openaiCompatible.ts    OpenAI, OpenRouter, Ollama, LM Studio, vLLM, DeepSeek, Groq, …
    anthropic.ts           своя форма сообщений + tool use вместо json-режима
    gemini.ts              своя форма + responseSchema; переезд GeminiFactCheck сюда
shared/
  aiRouting.ts             чистая логика: роль → провайдер, фолбэк, что при отсутствии ключа
  aiProviders.ts           каталог типов подключения и их возможностей (без секретов)
```

`electron/TranslationService.ts` остаётся фасадом — те же 13 экспортов, та же сигнатура. Меняется
только то, КУДА он их адресует. ⚠️ Сигнатуры не трогать в этом заходе: сменить одновременно и
маршрутизацию, и API — значит потерять критерий «ничего не изменилось».

## 1.2. Интерфейс

```ts
export interface Provider {
  id: string;                       // 'local' | 'openai:gpt-5' | 'openrouter:…'
  caps(): ProviderCaps;
  chat(msgs: Msg[], o: ChatOpts): AsyncIterable<string>;   // поток кусков, как сейчас onChunk
  structured<T>(schema: JsonSchema, prompt: string, o?: GenOpts): Promise<T>;
}

export interface ProviderCaps {
  schema: 'grammar' | 'native' | 'tool' | 'none';  // чем добиваемся валидного JSON, см. 1.3
  stream: boolean;
  contextTokens: number;
  price?: { inPerM: number; outPerM: number };     // для счётчика расхода, 1B
  local: boolean;                                  // отсюда берётся точка маршрута в UI
}
```

⚠️ `local: boolean` — не служебное поле, а **источник правды для метки маршрута**. Один флаг решает,
покажет интерфейс `--dot-local` или `--dot-cloud`; вычислять это в вёрстке по имени провайдера
нельзя, иначе «Ollama на localhost» когда-нибудь покрасится как облако.

## 1.3. Структурный ответ — главное место всего захода

Всё AI-ядро стоит на грамматике `node-llama-cpp`: невалидный JSON недостижим, а не редок. В облаке
грамматики нет, и подмены ей тоже нет — есть четыре разных механизма:

| `caps.schema` | Кто | Механизм | Гарантия |
| --- | --- | --- | --- |
| `grammar` | локальная Qwen | `createGrammarForJsonSchema` | на каждом токене |
| `native` | OpenAI, Gemini, Ollama | `response_format: json_schema, strict` / `responseSchema` | провайдером |
| `tool` | Anthropic | единственный tool с `input_schema`, ответ — его аргументы | почти |
| `none` | произвольный совместимый endpoint | схема в промпт + разбор | никакой |

`structured.ts` выбирает стратегию по `caps` и добавляет общий хвост: валидация ответа против той же
схемы, **один** ремонтный повтор («ответ не подошёл под схему, вот ошибка — повтори»), затем честный
отказ с кодом.

⚠️ Повтор ровно один, и это не экономия. Второй и третий повтор превращают редкий сбой в тихую
задержку на десятки секунд, за которую человек платит деньгами провайдера. Лучше сказать «не
получилось», чем молча стоить.

⚠️ Схемы уже написаны — `GEN_KIND_SCHEMA`, `genDataSchema`, схемы Студии. Ничего заново описывать не
надо, они и есть общий язык между грамматикой и `json_schema`.

## 1.4. Поток

`runChatMessage` уже принимает `onChunk` и `AbortSignal` — форма готовая. Облачные SSE ложатся на неё
один в один: разбор `data:`-строк, `[DONE]`, отмена через `signal` в `fetchInProfile`.

## 1.5. Ключи

`AiKeyStore.ts` → `electron/ai/KeyStore.ts`: карта `провайдер → ключ` в одном блобе `safeStorage`,
файл `ai-keys.enc`. Публичное поведение прежнее: наружу из main уходит только статус, никогда сам
ключ.

⚠️ **Миграция только добавляющая.** Прочитать `gemini-key.enc`, положить значение в новый файл под
ключом `gemini`, **старый файл не удалять**. Правило после случая 21.08, когда `unlink` при сбое
стёр боевые пароли: удаление ради чистоты не окупается никогда.

## 1.6. Очередь и «что сейчас делает ИИ»

`withQwenQueue` одна на приложение, потому что у llama.cpp один контекст на процесс. Это ограничение
ЛОКАЛЬНОЙ модели. Облаку оно не нужно: туда можно слать параллельно.

- очередь становится **по провайдеру**: у `local` — прежняя строгая единица, у облачных — предел
  одновременных запросов из настроек подключения (дефолт 4);
- `AiActivity` перестаёт быть регистром одной работы. В его шапке записано «физически единственное
  состояние» — с облаком это перестаёт быть правдой, и запись надо будет поправить вместе с кодом.
  Кнопка «Стоп» — на каждой работе, плюс общая.

## 1.7. Сеть

Только `fetchInProfile`. Сторож `network-egress-check` поймает нарушение сам, но помнить дешевле, чем
чинить. Следствие остаётся в силе: **облачные запросы идут через туннель**, когда VPN включён.

## 1.8. Чем проверяем часть без интерфейса

- `scripts/ai-routing-check.mjs` — чистая логика ролей и фолбэков (обязателен по правилу CLAUDE.md
  для нового модуля в `shared/`, попадёт и в мутационный прогон);
- `scripts/structured-check.mjs` — выбор стратегии по `caps` и разбор ответов-образцов (записанные
  ответы, без сети);
- `contract-check --update` — новые каналы;
- `npm run drive` целиком — критерий «ничего не изменилось»;
- `npm run ai-bench` получает флаг `--provider`: ключ берётся из переменной окружения, не из
  хранилища. ⚠️ Живой прогон облака в `npm test` не заводить никогда: прогон, который тратит чужие
  деньги и падает от чужого сбоя, перестанет быть сторожем через неделю.

**Критерий готовности 1A:** сборка, оба `tsc`, `npm test`, `npm run drive` зелёные; в интерфейсе не
появилось ни одного нового элемента; поведение локальной модели не отличается от предыдущего релиза.

# Часть 1B — видимая

## 2. Роли вместо функций — решение, от которого зависит весь UX

⚠️ **Роль объявляет ВЫЗЫВАЮЩИЙ, а не та функция, через которую он идёт.** Первая версия этой
таблицы выводила роли из экспортов `TranslationService` и была неверна: один только
`runTabOrganizePrompt` зовут СЕМНАДЦАТЬ разных мест — адресная строка, разбор форм, папки закладок,
имена загрузок, итоги дня, правила из фразы, поиск по настройкам, умный поиск на странице,
переименование вкладок, блокнот, изменения страницы, товары, виджеты. Назвать это одной ролью
«порядок во вкладках» значило спрятать пятнадцать функций браузера за названием шестнадцатой — и
человек, отдавший «вкладки» облаку, незаметно отдал бы туда же разбор своих форм.

Экспортов у `TranslationService` тринадцать, мест вызова — под сорок. **Ни тринадцати, ни сорока
списков делать нельзя.** Функции сворачиваются в десять ролей — по фичам, а не по транспорту:

| Роль | Что внутри | Ответ | Облако |
| --- | --- | --- | --- |
| Чат | панель, хаб, граф | **сочиняют** | **да** |
| Работа со страницей | выделение: **перевод**, пересказ, объяснение; изменения | **сочиняют** | **да** |
| Блокнот, Студия и граф | конспекты, майндкарты, тесты | **сочиняют** | **да** |
| Перевод страницы целиком | кнопка в тулбаре, батчи по DOM | движок, а не сочинение | нет: есть Bergamot |
| Порядок и имена | вкладки, закладки, загрузки | выбирают из набора | нет: то же за деньги |
| Итоги дня | дайджест прочитанного | выбирают из набора | нет: то же за деньги |
| Правила из фразы | «когда открываю X — делай Y» | выбирают из каталога | нет: каталог закрыт |
| Генератор виджетов | плитки стола | выбирают из каталога | нет: каталог закрыт |
| Поиск и адресная строка | история, вкладки, настройки | выбирают из набора | нет: ответ нужен раньше |
| Разбор форм | автозаполнение | выбирают из набора | нет: ответ нужен раньше |

⚠️ **Разделитель — ОТКРЫТЫЙ ОТВЕТ ПРОТИВ ЗАКРЫТОГО ВЫБОРА, а не приватность и не «чат против
кнопки».** Там, где модель выбирает из готового набора — разложить вкладки по кучкам, назвать файл
загрузки, положить закладку в папку, понять, что за поле в форме, — потолок задачи взят уже сейчас:
GPT-5 разложит вкладки не лучше, а так же, просто за деньги и лишние 800 мс. Там, где ответ
сочиняют, потолок задаёт модель, и разрыв виден глазом.

⚠️ **Доказательство правила лежит в самом проекте.** Генератор виджетов чинился именно тем, что
открытую задачу («напиши код плитки») превратили в закрытую («выбери тип из каталога и заполни
поля») — и локальной 4B сразу хватило. Подключать туда облако значило бы заново открывать задачу,
которую закрыли намеренно. То же с каталогом правил. Отсюда же пересмотр Фазы 2: ярус 2 генератора
не «виджеты станут лучше от облака», а сознательное открытие задачи обратно — и оценивать его надо
именно так.

⚠️ **Вторая причина отказа — скорость, и она другая.** Адресная строка и разбор формы считаются,
пока человек НАБИРАЕТ: круг до чужого сервера приходит позже, чем нужен. Это не «дешевле локально»,
а «в облаке хуже», и в интерфейсе две причины должны звучать по-разному.

⚠️ **Побочный итог, важнее самого правила: механизм согласия исчез.** В прошлой версии историю,
вкладки и итоги дня защищала галочка «я подтверждаю облако для приватной роли». Теперь у них просто
нет облачного варианта — а запрет надёжнее подтверждения, и одной сущностью в настройках меньше.

⚠️ **«Перевести страницу» и «перевести этот кусок» — РАЗНЫЕ роли, и сливать их нельзя.** Кнопка в
тулбаре идёт через `translatePageBatch`: обход DOM, батчи по 10–15 юнитов, плейсхолдеры `⟪N⟫` вместо
инлайновых тегов, движок из настроек (Bergamot **или** локальная Qwen — это выбор человека, а не
константа). Перевод выделенного фрагмента идёт через `runAiAction` и переводит его сегодня Qwen, а
не Bergamot: у Bergamot специализация узкая — целая страница по кнопке. Фрагмент живёт в роли
«Работа со страницей», и выбор модели там у человека **есть**. Первая версия таблицы свела оба
пути в одну роль и тем самым отняла выбор ровно там, где он уместен.

⚠️ **Таблица ограничивает АВТОМАТИКУ браузера, а не человека.** В AI-панели он выбирает модель под
любую задачу и просит её о чём угодно — перевести, пересказать, объяснить; роль «Чат» свободна по
построению. Семь закрытых ролей — это места, где браузер пошёл бы в сеть САМ, без нажатия. Два
вопроса не надо смешивать: первый про деньги и скорость, второй про свободу.

⚠️ **Запасной выход есть, и он один — AI-панель.** Закрывая облако семи ролям, мы отнимаем не
возможность, а АВТОМАТИЗМ: разница между «нельзя» и «не само» проходит здесь. В объяснении под
строкой «Перевод страницы целиком» это названо прямо — общая формулировка про «выбор из готового
набора» к переводу не подходит и про выход молчит.

⚠️ **Незаметная работа обязана оставаться бесплатной и офлайновой.** Итоги дня, разбор форм и
переименование вкладок, ходящие в облако на каждой странице, — это счёт за то, чего человек не
просил, и поломка фичи у всех, кто ключ не подключал.

`shared/aiRouting.ts` держит таблицу и правила фолбэка: провайдер без ключа, недоступный endpoint,
исчерпанный лимит → падаем на локальную. ⚠️ **Падение молчаливым быть не должно.** «Ответила другая
модель» — это то, что человек обязан видеть, иначе он получит худший ответ и решит, что испортился
браузер.

## 3. Где человек об этом узнаёт и где этим пользуется

### 3.1. Инвентарь: почти всё уже нарисовано

Новых компонентов не нужно — в `src/components/settings/kit.tsx` есть всё:

- `StatusCard` (иконка / «Подключено» / подпись / кнопки) — **точный образец уже стоит рядом**: так
  сделан блок «Фактчек — ключ Gemini» и «SearXNG — веб-поиск для AI» в `AiSection.tsx`;
- `TextField` + `InputRow` — ввод ключа и адреса endpoint;
- `Subsection`, `OptionList` / `OptionRow`, `Segmented`, `InkSwitch`, `MonoChip`, `SpotCard`;
- `SectionHeader` с `FactGrid`/`Fact` — шапка раздела AI уже показывает четыре факта: Модель, Перевод
  страниц, Фактчек, Веб-поиск;
- `AiActivityPill.tsx` в панели уже красится в `--dot-local` и в комментарии прямо говорит, что это
  метка «на этой машине». Это и есть готовое место для маршрута — рядом встаёт `--dot-cloud`.

⚠️ Новый цвет `--dot-cloud` идёт в статусные токены (один набор на все палитры, палитра их не
трогает). Фиолетового не брать — правило проекта, и оно распространяется на новые токены тоже.

### 3.2. Место первое: Настройки → AI → «Модели и подключения»

Раздел `ai` уже есть в реестре `shared/settingsIndex.ts`, в нём блоки «Локальная модель», «Движок
перевода страниц», «Индексация истории», «Скиллы», «Фактчек и веб-поиск». Добавляются два блока
(и две записи в реестр — иначе их не найдёт поиск по настройкам):

**Блок «Подключения».** Список карточек `StatusCard`, по одной на подключение, плюс «Добавить». Форма
добавления — три типа, ровно как в разведке: *OpenAI-совместимый* (адрес + ключ + модель), *Anthropic*
(ключ + модель), *Gemini* (ключ + модель). Пресеты одним нажатием подставляют адрес: OpenAI,
OpenRouter, DeepSeek, Groq, Ollama, LM Studio. ⚠️ Кнопка «Проверить» обязательна и делает один
дешёвый запрос: без неё человек узнает об опечатке в ключе через полминуты в чате и не поймёт, что
случилось.

**Блок «Что чем считается».** Десять строк из таблицы раздела 2: слева роль, справа выбор модели
(`OptionRow` + `Segmented` либо список подключений). ⚠️ Выбор есть только у ТРЁХ верхних строк;
остальные семь показываются с прочерком и объяснением из `cloudFitNote` («модель выбирает из
готового набора: облако сделает то же самое, но за деньги»). Прятать их нельзя — именно этот список
и есть ответ на вопрос «а что вы шлёте наружу»: семь строк, где ответ «ничего и никогда», работают
на доверие сильнее любого обещания в тексте.

⚠️ Это не «продвинутые настройки» — это единственный экран, на котором обещание приватности видно
целиком, поэтому он должен читаться как таблица, а не как россыпь тумблеров.

Факты в шапке раздела меняются на маршрутную сводку: сколько ролей считается на этой машине, сколько
в облаке, сколько подключений заведено, расход за месяц.

### 3.3. Место второе: точка применения

Настройки — для того, кто уже знает. Пользуются в другом месте:

- **AI-панель:** рядом с `AiActivityPill` — чип текущей модели с точкой маршрута. Нажатие меняет
  модель **для этой беседы**, не глобально. ⚠️ Разовый выбор не должен переписывать таблицу ролей:
  «попробовать на другой» и «изменить своё решение навсегда» — разные намерения, и путать их нельзя.
- **Поповер над выделением:** ничего не добавляем, кроме точки маршрута на результате. Второй
  элемент управления в поповере из четырёх кнопок его сломает.
- **Студия и блокнот:** выбор модели у кнопки запуска — здесь он осмыслен, потому что разница в
  качестве видна глазом и человек её ищет.
- **Каждый ответ** несёт точку маршрута. Не всплывашка, не «i», а постоянная метка.

### 3.4. Место третье: как человек вообще узнаёт, что это есть

Отдельного экрана-приглашения не делаем. Обнаружение — **в момент, когда упёрся**:

- локальная модель ответила ошибкой, отказом или упёрлась в контекст → в том же месте появляется
  строка «Эта задача великовата для модели на вашей машине. Можно посчитать её в облаке — нужен свой
  ключ» с переходом прямо в блок подключений;
- ярус 2 генератора виджетов (следующая фаза) просто недоступен без подключения и говорит об этом
  словами, а не серой кнопкой;
- в онбординге первого запуска — **ни слова**. Там человек ставит браузер, а не выбирает
  LLM-провайдера.

⚠️ Это прямое следствие принципа «незаметный ИИ»: предлагать в момент нужды, а не продавать заранее.
И оно же честнее — мы не обещаем облако тому, кому хватает локальной модели.

### 3.5. Чего не делаем

- каталога моделей с ценами и рейтингами — он устареет через месяц; список моделей тянем у самого
  провайдера, где он это отдаёт;
- «умного» автовыбора модели под задачу — это решение за человека, ровно то, чего проект не делает;
- своего прокси и своих ключей — платит человек напрямую провайдеру, мы не посредник.

## 4. Порядок и цена

1. **1A, слой провайдера** — 2–3 захода. Ничего не видно, всё работает как прежде.
2. **1B, маршруты и лицо** — 2 захода: подключения, затем таблица ролей и точки маршрута.
3. **MCP-сервер** — следующая фаза, от 1A/1B независим.
4. Виджеты яруса 2 — после, они опираются и на слой, и на песочницу.

## 5. Открытые вопросы

1. **Считать ли расход в деньгах или только в токенах.** Деньги честнее, но требуют держать
   прайс-лист, а он меняется и врёт.
2. **Что показывать при фолбэке на локальную.** Строка в ответе или отдельная нотификация — первое
   тише, второе заметнее.
3. **Разрешать ли облако для ролей «история» и «вкладки» вообще.** Сейчас заложено «да, с
   предупреждением». Запрет наглухо был бы проще и защитнее, но это ограничение за человека.
