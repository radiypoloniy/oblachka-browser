# Постраничная история

Список и обычный поиск в библиотеке используют новый read-only IPC history:page.
На экране максимум 500 записей; можно перейти «Старее» и «Новее» без общего ограничения
архива. Предыдущие страницы не кэшируются массивами; хранятся только их курсоры.
Записи упорядочены по времени и id, поэтому одинаковые timestamps не теряются.
При изменении запроса, удалении или очистке возвращаемся на первую страницу.
Неподтверждённая AI-выдача по-прежнему подписывается отдельно.

Схема, индекс и данные истории не мигрируются. Работает существующий SQLite-воркер;
устаревшие запросы отбрасываются существующей очередью. Legacy getHistory/searchHistory
остаются ограниченными ответами для других потребителей, а библиотека использует страницы.

Проверены: обход 1206 записей; 1205 совпадений; одинаковые даты; удалённая граница;
поиск самой старой страницы; пустой результат; некорректный курсор; реальные кнопки;
сброс страницы после ввода; сохранность AI-выдачи; смена профиля и поздний ответ.

Разовый синтетический замер 500000 записей (history-paging-bench.json): страницы начала,
середины и глубины 2.6–10.2 мс; распространённый запрос 1.7 мс; редкий 256 мс;
отсутствующий 660 мс. Максимальный интервал main-таймера 29 мс. Это отдельный замер,
не гарантия одинаковых задержек на всех устройствах. LIKE по редкому слову всё ещё читает
много строк, но не блокирует основной поток.

Обновлены два тестовых перехватчика: раньше они задерживали recent/search, а библиотека
теперь читает page. Начальные пустые запросы нового профиля не считаются вводом пользователя.
После обновления history-reader и history-query-ui прошли; один повторный запуск
history-query-ui получил undefined из CDP при закрытии вкладки, отдельный повтор прошёл.

Полный набор и релизные проверки фиксируются отдельно в документе выпуска 0.8.9.
