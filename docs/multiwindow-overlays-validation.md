# Владельцы поповеров и равноправные оконные команды

Карточки сайта и загрузок, а также перевод выделения остаются компактными общими поповерами: одновременно у каждого вида один владелец. Открытие в другом окне закрывает предыдущую карточку и уничтожает её view. Поздние IPC, bounds и переключение вкладки соседнего окна не управляют новым владельцем. Якоря хранятся отдельно по окнам. Закрытие владельца освобождает view; незавершённый перевод выделения отменяется.

Вью карточки сайта регистрируется как интерфейс собственного окна: сведения о странице и открытие настроек профиля адресуются ему. Новый вопрос о повторной загрузке сначала освобождает старого владельца, затем сохраняет новый вопрос. Закрытие соседнего окна не отменяет его.

Пустой источник после переноса закрывается независимо от порядка создания. Ctrl+Shift+M выбирает единственное другое окно; при нескольких цель выбирают в меню. Внешние ссылки, MCP и предложение обновления используют последнее рабочее окно. Общие callback-и и прогревы запускаются один раз на процесс. Legacy-маркер `main/light` сохранён в IPC только для стартового выбора профиля.

Проверено `scripts/multiwindow-overlays-drive.mjs` на временном профиле: адресация сведений о сайте, отдельные якоря, смена владельца и поздние команды, переключение чужой вкладки, два вопроса о загрузке, отмена перевода выделения и закрытие первого окна.

`scripts/multiwindow-model-drive.mjs` прошёл с настоящей EuroLLM-1.7B-Instruct.Q4_K_M: два ответа из разных окон, пустые независимые первые истории, продолжение истории второго окна после закрытия первого, та же загруженная модель. Файл модели читался с диска; настройки и SQLite создавались только во временном профиле.

Стенд получил отдельный синхронный запрос Inspector: это устраняет `Promise was collected` при чтении синхронных состояний. Тесты кругового переноса оставляют вкладку в каждом источнике, поскольку пустое первое окно теперь тоже закрывается.
