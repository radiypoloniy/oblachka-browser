# Окна: третий этап — общая сессия v6

4 октября 2026. Продолжение `equal-windows-plan.md`; одинаковый интерфейс и пооконные AI-контроллеры остаются следующими этапами.

## Поведение

- Один AppSessionCoordinator собирает деревья всех браузерных окон. У окна постоянный UUID, собственные закрепления, группы, split, активная вкладка и нормальная геометрия. AppSessionStore — единственный писатель session.json; SessionManager оставлен декодером v1–v5.
- При явном app.quit сохраняется весь открытый набор до уничтожения окон. Закрытия в процессе выхода не уменьшают этот набор. Отмена close снимает захват выхода и возобновляет обычное сохранение.
- При обычном закрытии окно переносится в общую историю закрытых. Окно с закреплениями возвращается целиком при следующем запуске. Закреплённые окна не вытесняются лимитом истории; обычных хранится до 20. Последнее обычное окно остаётся открытой сессией для следующего запуска.
- ПКМ по кнопке новой вкладки → «Закрытые окна» восстанавливает дерево вручную с тем же UUID и удаляет запись из закрытых. Устаревший экземпляр меню не восстанавливает его повторно.
- Все окна восстанавливаются после чтения общего файла. Автосейв включается только после завершения этого прохода. Неактивные страницы рождаются спящими, активная разрешается по ключу, а не по первому совпавшему URL. Старые activeRef по URL/индексу читаются для миграции.
- Профили сохраняются у одиночных вкладок и обеих сторон split. Индекс активного закрепления считается только среди записываемых пинов, без приватных/временных вкладок.
- Приватные и OAuth-вкладки исключены существующим сериализатором TabManager. Окно без сохраняемых страниц, содержащее только приватные/служебные вкладки, не восстанавливается. Их URL не попадают в новый основной файл или его backup.
- Геометрия ограничивается доступной рабочей областью монитора; восстановленные окна не остаются на исчезнувшем экране. Фокус возвращается сохранённому окну после готовности интерфейсов.

## Защита файла

Формат v6 содержит `windows`, `closedWindows` и необязательный `focusedWindowId`. Каждый элемент содержит дерево одного окна, не копию глобального дерева.

Перед первой записью v6 исходный v1–v5 копируется побайтово в `session.json.pre-v6.<timestamp>`. Если копия не удалась, основной файл не заменяется. Каждая запись идёт через временный файл и rename, с fsync нового основного содержимого; предыдущий корректный файл сохраняется в `session.json.bak`.

Если основной файл повреждён, читается корректный backup. Повреждённый исходник копируется в `session.json.corrupt.<timestamp>` до замены. Неизвестная будущая версия копируется в `session.json.from-vN.<timestamp>` и защищается от перезаписи на весь запуск. Ошибка чтения исходника, кроме отсутствия файла, также запрещает его замену.

Повреждённый v6, дубликаты UUID и неизвестные узлы отвергаются целиком. Нарушение инварианта TabManager пропускает общую запись, а не выбрасывает окно из снимка. Ошибка сессии показывается одним предупреждением за запуск и записывается в консоль.

## Проверки

- `scripts/app-session-check.mjs`: 14 сценариев миграций v1–v5, сохранности исходника, восстановления из backup, отказа rename, защиты будущей версии, повреждённого дерева/дубликатов UUID, лимита истории и закрытия/отмены выхода нескольких окон.
- `scripts/multiwindow-session-drive.mjs`: настоящие окна и несколько перезапусков на временном профиле. Закрытое закреплённое окно возвращается с группой; активный второй дубликат URL сохраняется; геометрия восстанавливается; приватные URL отсутствуют в основном/резервном файлах; ручное восстановление не создаёт дубль; явный выход сохраняет все открытые окна; настоящий старт на v5 создаёт побайтовый backup и записывает v6.
- `scripts/window-lifecycle-drive.mjs` и `scripts/window-routing-drive.mjs`: закрытие первого/последнего окна, отмена close, работа общих сервисов и адресный IPC.
- `scripts/split-stack-restore-drive.mjs` и `scripts/split-group-enter-drive.mjs`: split-стопки, пары и группы после перезапуска.

CDP-стенд теперь сообщает протокольную ошибку вместо тихого undefined. Подготовительные выражения не возвращают циклические объекты Electron, а закрытие проверяется через main IPC-handler без ожидания ответа от уничтоженного renderer.

Сборка, типы обоих таргетов, structure-check и полный pre-commit обязательны. Настоящий профиль пользователя не открывался.

## Границы проверки

Отказ rename инъецирован в тесте. Физическое отключение питания, отключение монитора и macOS не проверялись. Куки профилей, чаты и история остаются в прежних хранилищах; этот этап переносит только деревья браузерных окон. Перенос вкладок и полноценные AI-контексты во всех окнах требуют следующего этапа; роли main/light пока сохранены.
