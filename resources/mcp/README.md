# @oblako/mcp

MCP-сервер браузера [Oblako](https://github.com/radiypoloniy/oblachka-browser): внешний ИИ-клиент
(Claude Desktop, Claude Code, Cursor) получает доступ к **живому браузеру человека** — с его
куками, логинами, регионом, адблоком и туннелем.

Это не «ещё один headless-Chromium». Playwright MCP даёт чистый браузер без кук — им нельзя
посмотреть свою почту или увидеть цену со своим городом. Мосты-расширения дают логины ценой
второго процесса, слушающего сетевой порт. Здесь порта нет вовсе: клиент и браузер говорят через
именованный канал Windows с токеном, до которого веб-страница дотянуться не может.

## Что нужно

1. Установленный и **запущенный** браузер Oblako.
2. Включённый сервер: **Настройки → AI → «Браузер как инструмент»**.

Без запущенного браузера пакет честно скажет об этом в stderr, а не будет молча висеть.

## Подключение

```json
{
  "mcpServers": {
    "oblako": {
      "command": "npx",
      "args": ["-y", "@oblako/mcp"]
    }
  }
}
```

Точку подключения пакет находит сам (`%APPDATA%/oblako-browser/mcp-endpoint.json`). Свой путь —
`--endpoint <файл>`.

При первом обращении браузер спросит человека, подключать ли эту программу: карточка появится
поверх всех окон, назовёт профиль и перечислит, что программа сможет делать без отдельного вопроса.

## Что отдаётся

Чтение — молча, по согласию, данному при подключении: открытые вкладки, текст и снимок активной
страницы, выделенный фрагмент, ссылки с неё, поиск по истории и закладкам, список отслеживаемых
товаров. Чтение произвольного адреса профилем человека спрашивается отдельно.

Изменения — открыть вкладки (списком), переключить, закрыть, собрать в группу сайдбара, сохранить
закладки, поставить товар на отслеживание цены — **каждое проходит через карточку подтверждения** в
самом браузере, а не в окне программы, которая просит.

## Чего нет и не будет

Паролей, куков, автозаполнения и приватных вкладок здесь нет — это не выключенный тумблер, а
отсутствие инструмента: тумблер можно включить уговорами, а того, чего нет, не позовёшь. Кликов по
странице и заполнения форм тоже нет: агент, исполняющий то, что прочитал на чужом сайте, — это
prompt injection с правами залогиненного человека, и от такой конструкции проект отказался
осознанно.

Границы, которые человек может поставить сам: белый список сайтов на программу, права по каждому
инструменту (спрашивать / можно / никогда) и профиль — разрешение действует только в том профиле,
для которого его дали. Всё это в разделе **Библиотека → Агенты**, там же журнал обращений.
