# История: пропуск устаревших запросов до IPC

Дата: 2 октября 2026. Одна правка: очередь обычного поиска внутри одного экземпляра раздела истории. Формат базы, запись истории, индексация и ранжирование не менялись.

## Поведение

Раньше каждый ввод сразу отправлял отдельный запрос в читающий SQLite-воркер. Счётчик поколений предотвращал показ устаревших результатов, но не само чтение.

Теперь раздел держит одно выполняющееся чтение и только один ожидающий запрос. Следующий ввод заменяет ожидающий запрос; Promise заменённого завершается с `undefined`. Это отличается от настоящей пустой выдачи `[]`. Завершённое чтение принимается только для актуального поколения. Очистка поля тоже проходит через очередь, после неё читаются последние посещения.

При закрытии раздела, смене профиля или явном запуске AI существующая защита поколений инвалидирует ожидающее чтение. Оно не отправляется в IPC. Уже выполняющийся SQL не прерывается. Очередь принадлежит компоненту, поэтому омнибокс, поиск правил, другие окна и AI-кандидаты не объединяются с её запросами. Фиксированного debounce нет: если очередь свободна, поиск начинается сразу.

## Измерения

Повтор: `npm run build`, затем `node scripts/history-query-bench.mjs`. Полные отсчёты: `history-query-queue.json`.

Одноразовый профиль: 500 000 посещений, 20 000 индексированных страниц, 90 000 текстовых фрагментов с FTS. Три пары прогонов с чередованием порядка, прогретый кэш. Шесть вводов через примерно 30 мс; фактические времена каждого ввода сохранены. Окно поднято поверх других окон, видимость проверяется. Реальный пользовательский профиль не открывается.

Сравнение использует настоящие preload → IPC → main → SQLite-воркер. Эталон воспроизводит прежнюю отправку каждого ввода с защитой поколений; новый вариант использует текущий модуль очереди renderer. Это сравнение пути чтения, не двух полных сборок UI. Время считается от первого ввода до получения актуальной выдачи, без DOM и вывода пикселей.

| Прогон | Прежняя отправка | Очередь | Чтений до / после |
|---|---:|---:|---:|
| 1 | 974,9 мс | 462,1 мс | 6 / 3 |
| 2 | 874,8 мс | 348,9 мс | 6 / 2 |
| 3 | 840,5 мс | 428,5 мс | 6 / 3 |
| Медиана | 874,8 мс | 428,5 мс | |

Все три пары вернули одинаковые 100 id в одинаковом порядке; SHA-256 списков сохранён. Число чтений не обязано всегда быть два: если промежуточный запрос успел начаться до следующего ввода, он спокойно завершается.

Отдельный прогон настоящего React-поля завершился появлением 100 строк в DOM за 830,7 мс и отправил четыре чтения вместо шести. Итог не изменился после поздних ответов. Это один UI-прогон без парного прежнего UI, поэтому он подтверждает работу очереди в продукте, но не доказывает двукратного визуального ускорения.

Тестовый индекс присутствует на диске; параллельный инференс AI, запись индексатором и холодный диск не моделировались. Замеры не означают ускорения самого SQL, загрузки модели или реранка. Предварительные замеры с конкурирующими проверками и без надёжного контроля окна не включены в итоговый отчёт.

## Регрессии

`history-query-check.mjs`: серия ввода, завершение отменённых Promise, инвалидирование очереди, очистка поля, независимость экземпляров, пустая выдача, актуальная/устаревшая/синхронная ошибка и восстановление после ошибки.

`history-query-ui-check.mjs`: настоящее поле истории, другой потребитель того же IPC, очистка поля, закрытие вкладки, поздний обычный ответ после AI, смена профиля с ожидающим чтением. В AI-сценарии детерминированная заглушка заменяет только выдачу умного поиска; это проверка управления запросами, не качества модели. Все данные теста находятся во временном профиле.

Общий `npm test`: 121 из 122 файлов прошли, 3569 успешных ассертов, семь прежних ошибок размера в `structure-check` (TabManager, TranslationService, main, preload-content, preload, две метрики PasswordsSection). Эти файлы не изменялись. Новых превышений нет, пороги не менялись. Проверки FTS, индексации, профилей, worker, ASAR, кандидатов и реранка прошли.

Сборка, оба таргета TypeScript, линтер изменённых исходников и `git diff --check` прошли. Общий `npm run lint` сохраняет 83 ранее учтённые ошибки; проверка храповика `lint-check` прошла без роста.

Для коммита используется документированное исключение pre-commit из-за прежнего `structure-check`; полный набор проверок выполнен отдельно.
